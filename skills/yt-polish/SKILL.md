# yt-polish — 훅·제목·썸네일 다듬기 규칙

입력은 `ytc polish context <draft.md>`의 JSON이다. 출력은 polish JSON 하나다.
목표: **클릭을 약속하고(제목·썸네일), 첫 15초에 그 약속을 지키는(훅)** 한 벌. 제목과 썸네일은 한 쌍으로 쓴다. 따로 쓰면 썸네일이 제목을 되풀이해서 클릭 면적의 절반이 같은 말이 된다.

## 1. 쓰기 전에

- `profile`(말투, 피하고 싶은 스타일, 얼굴 출연 여부)을 읽고 따른다. 말투가 다른 훅은 본인이 소리 내어 읽기 힘들다. profile이 없으면 `title`·`hook`의 기존 문체를 따른다.
- 숫자·결과·출처를 **지어내지 않는다.** 숫자가 있으면 좋은 자리에 근거가 없으면 숫자 없는 문장으로 쓴다. 기획안(`title`, `hook`, 전체 섹션)에 이미 있는 숫자·이름만 쓴다.
- `refs`(레퍼런스 통계)를 본다. `hook_type`, `title_pattern`에서 **내 레퍼런스에 많은 쪽**을 우선하되, 후보 전부를 한 유형으로 채우지 않는다. 공식(`formulas`)은 가능한 한 서로 다른 것을 고른다.
- 공식은 `formulas`(21가지)에서만 고른다. `fails_when`에 걸리는 공식은 쓰지 않는다(예: 근거 없는 숫자가 필요한 통계, 화면이 없는 영상의 전후 비교).

## 2. 훅 5개

첫 15초(쇼츠는 훅 구간)가 하는 일은 세 가지다: **제목이 약속한 클릭을 확인하고, 시청자가 닫을 수 없는 질문을 열고, 결과가 실제로 있음을 보여 준다.** 세 번째만 하는 훅은 요약이라 시청자가 새어 나간다.

- 규칙(hooks.json `rules`): 첫 문장에서 제목의 약속을 확인 / 아이디어는 하나 / 큰 말보다 구체적인 말 / 약속한 결과물은 20초 안에 보여 주기 / 자기소개·인사·구독 부탁으로 시작하지 않기.
- **숫자·이름·날짜가 형용사보다 세다.** “엄청난”, “역대급” 대신 몇 개, 어디, 언제.
- 훅은 정확히 5개. 각각:
  - `formula`: hooks.json의 `id` 그대로
  - `hook_type`: `question` `result_first` `shock_line` `situation` 중 하나(공식의 `hook_type`과 다르게 써도 되지만 이유가 있어야 한다)
  - `script`: 대본 형식 그대로 `말: …` / `자막: …` 줄. 줄바꿈으로 구분한다. 말 없는 영상이면 `자막:`만
  - `why`: 왜 이 공식이 이 영상에 맞는지 한 줄
- 길이: context의 `hook`(시작·끝)과 `cps`(초당 글자 수)로 `말:` 글자 수가 훅 구간에 들어가게 쓴다. 넘으면 점수에서 깎인다.
- 훅의 `hook_type`을 기획안의 `hook_type`과 일부러 바꾸는 후보도 1~2개 섞어도 된다. 어떤 후보든 영상에서 실제로 보여 줄 수 있어야 한다.

## 3. 제목 10개

- 정확히 10개, 각각 `title`과 `why`(한 줄).
- 폭은 **한글·한자·전각·이모지 2, 그 밖 1**로 센다(근사치). 모바일 피드는 폭 56, 데스크톱 검색은 폭 100에서 잘린다. 모바일에서 잘려도 핵심은 앞쪽에 둔다.
- 숫자·이름·날짜를 넣는다. 느낌표·물음표는 합쳐서 2개 이하. 대문자 남발 대신 한국어에서는 `!!!`, `???`, 이모지 도배를 피한다.
- 패턴을 나눈다: 숫자형, 질문형, 괄호형, 평서형이 섞이게. 그중 내 레퍼런스에 많은 패턴을 먼저.
- 썸네일 문구와 겹치는 낱말을 쓰지 않는다. 제목이 약속을 말하고, 썸네일이 다른 말로 같은 약속을 건다.
- 기획안의 내용과 다른 약속(낚시)은 쓰지 않는다.

## 4. 썸네일 지시서 1개

`thumbnail` 하나: `words`, `expression`, `framing`, `background`.

| 필드 | 규칙 |
|---|---|
| `words` | 문구. **3단어 이하**, 제목과 다른 말, 제목과 같은 약속. 피드 크기에서는 네 번째 단어부터 뭉개진다. 낱말 목록으로 쓴다 |
| `expression` | 표정·감정. 얼굴이 안 나오는 profile이면 손·음식·반응하는 물체 |
| `framing` | 구도: 샷 크기와 배치(예: “바스트, 왼쪽 얼굴 / 오른쪽 컵라면”) |
| `background` | 배경과 대비: 피드 크기에서 글자가 읽히려면 배경이 무엇을 해야 하는지 |

## 5. 출력 (polish JSON)

```json
{
  "hooks": [
    {"script": "말: 편의점 컵라면 4단계, 마지막까지 간 사람은 거의 없대요.\n자막: 맵기 4단계 도전",
     "formula": "the-question", "hook_type": "question",
     "why": "시청자가 궁금해할 ‘끝까지 갈 수 있나’를 그대로 물어 제목의 도전 약속을 확인한다"}
  ],
  "titles": [
    {"title": "컵라면 맵기 4단계, 끝까지 먹어 봤다", "why": "숫자 + 직접 해봤다 공식, 폭 35로 모바일 안에 들어간다"}
  ],
  "thumbnail": {"words": ["4단계", "생존?"], "expression": "눈물 고인 얼굴로 웃는 표정",
                "framing": "바스트, 오른쪽 아래에 빈 컵 네 개", "background": "빨강 단색, 글자는 흰색 굵은 고딕"}
}
```
(예시는 줄였다. 실제로는 훅 5개, 제목 10개를 모두 적는다.)

## 6. 사용자에게 보여 줄 형식 (터미널)

`ytc polish evaluate` 결과(점수 내림차순)를 이 형식으로 보여 준다. 근거 문장과 지적은 결과의 `evidence`·`lint.issues`를 그대로 옮긴다.

```
🎣 훅 후보 (기획안 훅 구간 0:00–0:02, 말 속도 초당 7.0자)
 1) [92점] 질문 · the-question(질문)
    말: 편의점 컵라면 4단계, 마지막까지 간 사람은 거의 없대요.
    자막: 맵기 4단계 도전
    → 시청자가 궁금해할 ‘끝까지 갈 수 있나’를 그대로 묻는다
    근거: 이 훅 유형은 내 레퍼런스 10개 중 1개 · 지적: 숫자가 없음
 2) …

🏷 제목 후보
 1) [100점] 컵라면 맵기 4단계, 끝까지 먹어 봤다 (폭 35)
    → 숫자 + 직접 해봤다
    근거: 같은 제목 패턴(number)은 내 레퍼런스 10개 중 7개
 2) …

🖼 썸네일 지시서 [100점]
 문구: 4단계 / 생존?   표정: …   구도: …   배경·대비: …
```
묻는다: "훅 몇 번, 제목 몇 번, 썸네일은 이대로 쓸까요? 고칠 곳이 있으면 말해 주세요." 사용자가 고른 것만 저장한다.

## 7. 저장될 때

- 제목은 프런트매터 `title`·`title_pattern`과 본문 첫 `# ` 줄을 바꾼다. 고른 훅은 훅 섹션의 대본 문단을 바꾸고, 샷 표는 건드리지 않는다.
- `## 패키징`에 썸네일 지시서, 고른 훅 공식, **이전 제목·이전 훅 대본**(이력)을 남긴다. 되돌리려면 이력에서 복사한다.
- `## 내 메모`는 절대 건드리지 않는다. 콘티가 이미 있으면 대사가 자동으로 바뀌지 않으니 `/yt-conti`로 다시 만들라고 경고가 나온다.
- 점수는 제안이지 합격선이 아니다. 낮은 점수의 후보도 사용자가 고르면 저장한다.
