# yt-diagnose — 근접도·갭 서술 규칙

입력은 `ytc similarity compare <category> <target>`의 JSON이다. 출력은 notes JSON 하나다.
진단은 **채점이 아니라 다음에 무엇을 바꿀지 정하는 것**이다. 단일 종합 점수는 없다.

## 1. 숫자 읽는 법

- `axes.<축>.proximity` (0~1)
  - structure·pacing: 아키타입 중심과의 거리를 다른 유형 영상들까지의 거리에 견준 값. 1이면 아키타입 그대로, 0이면 다른 유형만큼 다르다. 0.7 이상이면 '이 유형답다'.
  - hook·narrative: 아키타입 영상 중 나와 같은 유형의 비율. 0.2면 소수파.
  - title: 제목 패턴이 겹치는 정도.
  - null: 그 축을 잴 정보가 없다(대본만 있는 기획과 장면 단위로 적은 기획(`pacing.basis: scenes`)은 pacing이 없다). 언급만 하고 넘어간다.
- `gaps`: 아키타입과 눈에 띄게 다른 지점. key별 의미:
  - `structure:<label>`: 그 섹션의 시간 비중(target)과 아키타입 평균(archetype) 차이가 10%p 이상
  - `hook` / `narrative`: 아키타입에서 절반 넘게 쓰는 유형과 다름
  - `pacing:avg_cut`: 평균 컷 길이가 30% 넘게 다름
- `intentional`: 사용자가 "일부러 다르게 했다"고 표시한 갭. **다시 지적하지 않는다.**
- `preliminary: true`: ref 10개 미만. 문장을 "~경향과 비교하면"처럼 약하게 쓴다.

## 2. 갭 설명 (gaps의 모든 key에 하나씩)

- 숫자를 사람 말로: "본론이 아키타입은 평균 82%인데 이 영상은 55%로, 인트로가 20초나 된다"
- 왜 문제일 수 있는지 한 마디: 레퍼런스에서 그 섹션이 하는 역할(yt-analyze 라벨 정의)과 연결.
- 다를 수 있다는 여지: 일부러 바꾼 거라면 `intentional`로 표시하면 다음부터 빠진다고 안내할 수 있다.

## 3. 다음 행동 (1~3개)

- 다음 영상(또는 이 기획 수정)에서 **바로 할 수 있는 한 가지 행동**씩. 큰 갭부터.
- 촬영·편집 단위로: "인트로 20초를 5초로 줄이고 첫 화면에 완성품" ✓ / "구조를 개선하세요" ✗
- 갭이 없으면: 잘 맞는 점 하나를 짚고, 변형해 볼 거리(기법 카드 등) 하나를 제안한다.

## 4. 출력

```json
{
  "summary": "A1 '한 메뉴 리액션 중계형'에 가장 가깝지만, 인트로가 길고 본론이 짧아 구조 근접도는 낮다(29%). 컷 속도는 레퍼런스와 비슷하다.",
  "gaps": {
    "structure:intro": "아키타입엔 인트로가 거의 없는데(1%) 이 영상은 33%다. 레퍼런스는 훅 직후 바로 먹기 시작한다.",
    "structure:body": "본론 비중이 55%로 아키타입 평균 82%보다 짧다."
  },
  "actions": ["인트로 20초를 5초 안으로 줄이고, 첫 화면에 완성된 음식을 둔다", "본론을 40초 이상 확보한다"]
}
```

## 5. 사용자에게 보여 줄 형식

```
🩺 진단: <제목> — 가장 가까운 아키타입 A1 한 메뉴 리액션 중계형

| 축 | 근접도 |
|---|---|
| structure | 29% |
| hook | 75% |
| narrative | 25% |
| title | 50% |
| pacing | 80% |

갭
- structure:intro (나 33% / 아키타입 1%) 아키타입엔 인트로가 거의 없는데 …
다음 행동
1. …
```
