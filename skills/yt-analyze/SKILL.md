# yt-analyze — 영상 한 편 분석 규칙

입력은 `ytc videomd context <id> --category <cat>`의 JSON이다. 출력은 아래 형식의 **분석 JSON 하나**다.
수치 계산(컷 길이, 제목 패턴, 섹션 경계 보정, md 작성)은 `videomd write`가 하므로 여기서는 하지 않는다.

## 0. 먼저 할 일

1. `examples`에 경로가 있으면 **모두 읽는다**. 사용자가 직접 고친 분석이다(`reviewed: true`).
   섹션을 어디서 자르는지, 어떤 라벨·유형을 고르는지 그 경향을 우선 따른다. 이 규칙의 일반론보다 사용자 교정이 앞선다.
2. 입력을 본다.
   - `transcript`: `[초] 문장` 형식 자막. 시간은 초 단위다.
   - `scenes`: `[시작–끝] 카메라 · frame 경로` 형식 장면 목록. 장면 경계 = 컷.
   - `sparse: true` 또는 `transcript: null`: 말이 거의 없다(ASMR, 음악만, 자막이 엉터리 자동 영어 등).
     이때는 `scenes`의 frame 이미지를 **최대 8장** Read로 보고(처음·끝은 꼭 포함, 나머지는 고르게) 화면 위주로 판단한다.
     엉터리 자동 자막(예: "Ki", "Mhm.")은 내용 근거로 쓰지 않는다.
   - 말이 충분하면 frame은 보지 않는다(비용 절약). 판단이 애매한 구간만 1~2장 본다.

## 1. 섹션 라벨 (고정, 설계서 5.1)

영상 전체를 빈틈없이 덮는 구간 목록을 만든다. 순서대로, 시간은 초.

| label | 뜻 | 판단 기준 |
|---|---|---|
| hook | 첫 시선 붙잡기 | 영상 맨 앞 0~5초(롱폼은 ~30초). 결과·질문·충격 문장·상황을 던지는 부분 |
| intro | 소개 | 인사, 오늘 할 것 설명, 채널 소개. 훅 뒤에 본론 전 준비 |
| body | 본론 | 핵심 내용. 반드시 sub를 붙인다 |
| demo | 시연·결과 보여주기 | 완성품, 먹는 장면 하이라이트, 비포/애프터처럼 '보여 주는' 구간이 본론과 따로 있을 때 |
| transition | 전환 | 본론 사이 짧은 연결(다음은~, 장소 이동, 화면 전환 효과) |
| cta | 행동 요청 | 구독·좋아요·댓글·링크 요청 |
| outro | 마무리 | 끝인사, 요약, 다음 편 예고 |

body의 sub (하나만):
- `list_item`: 항목을 하나씩 나열 (나라별, 사이즈별, 1위~5위)
- `story`: 시간 순 경험·과정 (끓이고 → 먹고 → 반응)
- `explain`: 설명·정보 전달 (방법, 이유, 팁)
- `compare`: 둘 이상을 견줌 (A vs B, 비싼 것 vs 싼 것)

나누기 원칙
- 쇼츠는 보통 섹션 2~5개, 롱폼은 4~10개. 너무 잘게 쪼개지 않는다.
- 같은 라벨이 다시 나와도 된다 (body → transition → body).
- 경계는 말이 바뀌는 지점 또는 `scenes`의 컷 시점에 둔다. 0.7초 안의 컷에는 스크립트가 맞춰 준다.
- 첫 구간 start는 0, 마지막 end는 영상 길이로 둔다.

## 2. 훅 유형 (hook_type, 하나)

| 값 | 기준 | 예 |
|---|---|---|
| question | 질문으로 시작 | "라면 5봉지, 혼자 다 먹을 수 있을까?" |
| result_first | 결과·완성품·클라이맥스를 먼저 보여 줌 | 완성된 산더미 라면 클로즈업으로 시작 |
| shock_line | 강한 단정·의외의 한 문장 | "이거 먹고 3kg 쪘습니다" |
| situation | 상황·설정 제시 | "통장 잔고 3만 원일 때 먹방" |

말 없는 영상은 첫 장면 화면으로 판단한다(대개 result_first 또는 situation).

## 3. 서사 유형 (narrative_type, 하나)

| 값 | 기준 |
|---|---|
| problem_solution | 문제·궁금증 제시 → 해결·답 |
| list | 항목 나열이 뼈대 (body가 주로 list_item) |
| journey | 과정·경험을 따라감 (body가 주로 story) |
| compare | 비교가 뼈대 |
| reaction | 먹고·보고 반응하는 것이 중심 (ASMR·리액션 먹방) |

## 4. 기법 (techniques)

다른 영상에 **떼어 쓸 수 있는** 것만 0~4개. 영상 내용 요약이 아니라 방법이어야 한다.
- kind는 `훅` `전환` `엔딩` `촬영` 중 하나
- name은 짧은 이름(카탈로그에서 같은 이름끼리 합쳐지므로 일반적인 이름으로: "결과 선공개", "탑뷰 손 클로즈업")
- desc는 한 문장, 이 영상에서 어떻게 썼는지
- at은 등장 시점(초), 모르면 생략
- 촬영 기법은 scenes의 카메라 정보·frame으로 확인한 것만 쓴다. 추측하지 않는다.

## 5. 출력 형식 (이 형식 그대로, JSON만)

```json
{
  "summary": "라면 다섯 봉지를 한 냄비에 끓여 혼자 다 먹는 1분 쇼츠",
  "synopsis": "완성된 산더미 라면을 먼저 보여 준 뒤, 물 붓기부터 마지막 국물까지 빠른 점프컷으로 이어간다. 끝에서 먹은 양을 숫자로 정리하고 구독을 요청한다.",
  "hook_type": "result_first",
  "narrative_type": "journey",
  "sections": [
    {"label": "hook", "start": 0, "end": 2.5, "content": "완성된 라면 냄비 클로즈업 + '5봉지' 자막"},
    {"label": "body", "sub": "story", "start": 2.5, "end": 48, "content": "끓이기 → 첫 입 → 먹는 과정, 1~2초 점프컷"},
    {"label": "outro", "start": 48, "end": 55, "content": "빈 냄비 보여 주며 먹은 양 정리"},
    {"label": "cta", "start": 55, "end": 60, "content": "구독 요청 자막", "shot": "정면 바스트, 고정"}
  ],
  "techniques": [
    {"kind": "훅", "name": "결과 선공개", "desc": "완성된 라면을 첫 2초에 보여 주고 시작", "at": 0},
    {"kind": "촬영", "name": "고정 정면 + 점프컷", "desc": "카메라는 고정하고 1~2초 점프컷으로 속도감"}
  ]
}
```

- `content`는 한 줄, 그 구간에서 무엇을 하는지(말+화면).
- `shot`은 frame을 실제로 본 구간만 쓴다(샷 크기·앵글). 비우면 스크립트가 카메라 판정·컷 길이로 채운다.
- 한국어로 쓴다. 영상이 외국어여도 요약·내용은 한국어.
- 값이 허용 목록 밖이면 `videomd write`가 `invalid_analysis`로 거절한다. 메시지를 보고 고쳐 다시 저장한다.
