# 모티브 화면 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 로컬 UI의 "만들기 › 모티브"(지금 2차 안내)를 실제 화면으로: 저장된 카드 보기·★, 새 카드 뽑기(Claude 1회) → 고르고 고쳐서 저장.

**Architecture:** 카드 규칙·저장은 기존 `scripts/motif.py`(`context`, `add`, `star`)를 쓴다. `add`의 검증을 `validate_cards()`로 뽑아 Claude 응답 검증에도 쓰고, 저장된 카드 전체 내용을 읽는 `card_details()`를 더한다. UI 서버에 `scripts/ui/api_motif.py`(상태, 뽑기 작업, 저장, ★). 뽑기는 유형화와 같은 작업 방식(끝나면 `awaiting` 미리보기, 작업 `done`). 프런트 `pages/motif.js`.

**Tech Stack:** Python 3.11 stdlib, `scripts/claude_cli.py`, 바닐라 JS ES 모듈, pytest.

**Spec:** 채팅에서 승인된 설명(2026-10-24), 아래 "승인된 범위". 카드 규칙: `skills/yt-inspire/SKILL.md`. 터미널 흐름: `commands/yt-inspire.md`.

### 승인된 범위
- 상단: 단계와 허용 카드 종류("3단계 · 흐름·조합·기법·각도"). 필요할 때만 안내: 프로필 없음("카드가 일반적으로 나옵니다"), 3단계인데 유형화 결과 없음("유형화를 먼저 하면 흐름·조합 카드가 나옵니다" + `#/typify`), ref 0개(레퍼런스 추가로).
- 저장된 카드 목록: 종류 배지, 제목, 아이디어, 찍는 법 단계, 바탕, 근거 영상(`#/refs/<id>`). 필터 전체 / ★만 / 종류별. ★는 누르면 바로 저장. 카드마다 `/yt-coach:yt-draft <카테고리> <카드 id> "<주제>"` 복사 버튼.
- "새 카드 뽑기": 주제(선택) + 버튼 → Claude 1회, 진행 표시 → 미리보기 카드(체크박스 기본 전부 선택, 제목·아이디어·찍는 법 수정 가능, 카드별 "저장하면서 ★") → "선택한 카드 저장". "다시 뽑기", "버리기". 저장 전엔 `index.md` 불변.
- 기법 카탈로그 정리는 넣지 않고 "터미널 `/yt-coach:yt-inspire`에서" 안내만(내 결정). 저장된 카드는 `index.md` 모티브 카드 섹션을 읽어 보여 준다(직접 고친 내용 반영).
- 빼는 것: 카드 삭제·저장된 카드 수정, 기법 병합.

## Global Constraints
- Claude는 "새 카드 뽑기" 클릭 때만. 카드 저장은 "선택한 카드 저장" 클릭 때만. ★ 토글은 사용자 행동이라 즉시 저장 가능.
- 카드 규칙(단계별 허용 종류, evidence는 이 카테고리 ref만, 제목 중복 금지)은 `motif` 검증 하나로 CLI·UI 공통.
- mine은 근거가 될 수 없다(기존 `add` 규칙 그대로).
- `index.md`는 `## 모티브 카드` 섹션만 바뀐다(기존 `add`/`star`와 같음). `## 내 메모` 불변.
- 새 의존성 금지. 프런트 규칙(innerHTML 금지, `h()`/`fill()`, 정적 파일 `http(s)://` 금지, 페이지 계약, `alive`/`isCurrent()`, `ctx.api`, 네이티브 dialog 금지 — 확인은 인라인)은 기존과 같다.
- 사용자 대면 한국어, 식별자 영문. 커밋 Conventional Commit, Claude 서명 없음.

## Review Focus
1. Claude가 허용되지 않은 종류·없는 근거 id·중복 제목 카드를 냄 → 1회 재시도, 그래도면 작업 실패 메시지, 저장 없음. (Task 1)
2. 사용자가 미리보기에서 제목을 기존 카드와 같게 고치거나 비움 → 저장 거부(`invalid_cards`), 입력 유지. (Task 1 + 2)
3. 사람이 `index.md` 카드 블록을 손으로 고침(줄 순서 바꿈, `- 이렇게:` 삭제, 근거에 제목 없이 링크만) → 목록이 깨지지 않고 있는 필드만 보여 줌. (Task 1)
4. 미리보기 저장 사이 터미널에서 카드가 추가됨 → 번호가 겹치지 않음(저장 시점에 다음 번호 계산 — 기존 `add`가 그렇다), 제목이 겹치면 거부. (Task 1)
5. ★ 연타·저장 중 이동 → 마지막 상태가 파일과 일치, 늦은 응답이 새 화면을 덮지 않음. (Task 2)

**Interfaces (Task 2가 씀):**
- `card_details(category)` → `[{"id", "starred": bool, "type", "type_ko", "title", "idea": str|None, "how": [str], "basis": str|None, "evidence": [{"id", "title": str|None}], "made": str|None}]` — `## 모티브 카드` 섹션의 `### ...` 블록마다. 필드 줄은 순서 무관 접두사 매칭(`- 아이디어:`, `- 이렇게:`(" → "로 나눔), `- 바탕:`, `- 근거:`(`[id](videos/id.md) 제목` 반복, 쉼표 구분; 제목 없으면 null), `- 만든 날:`). 모르는 줄은 무시. 섹션이 없으면 `[]`.
- `GET /api/motif?category=<c>` → `{"category", "ref", "stage", "allowed_types", "allowed_ko": [..], "has_profile": bool, "has_typify": bool, "cards": card_details, "draft_hint": "/yt-coach:yt-draft"}` (`has_typify` = `motif.context`의 typify가 None이 아님과 같은 기준).
- `POST /api/motif/run` `{"category", "topic"?: str(≤100자, 공백 정리)}` → `{"job"}`. ref 0개면 작업 없이 `ScriptError("no_refs", "먼저 레퍼런스를 넣어 주세요")`. `claude_cli.find_claude()` 먼저. 작업 kind `"motif"`, 항목 1개(id=category), step `"context"` → `"claude"` → 끝나면 `awaiting/preview/ask="save"`, preview `{"cards": 검증된 카드, "topic", "stage", "allowed_types", "titles": {ref id: title}}`, 작업 `done`.
  - Claude: `ask_validated([SKILLS_DIR/"yt-inspire"/"SKILL.md"], payload=motif.context(category, topic), task=MOTIF_TASK, validate=lambda d: motif.validate_cards(category, d.get("cards") if isinstance(d, dict) else None), schema=CARDS_SCHEMA)`. `MOTIF_TASK = "yt-inspire 규칙대로 입력의 모티브 카드를 만들어 {\"cards\": [...]} 형태로 답하세요. 기법 카탈로그 병합은 하지 마세요."` `CARDS_SCHEMA`: object `{cards: array of {type: enum TYPES, title: str, idea: str, how: array of str, basis: str, evidence: array of str}}`, required cards; item required type,title,idea,evidence.
- `POST /api/motif/save` `{"category", "cards": [카드...], "star": [저장 목록 안 인덱스...]}` → 빈 목록이면 `bad_request`. 카드를 `workspace/tmp`에 mkstemp(`motif_cards_*.json`)로 쓰고 `motif.add`(finally에서 삭제) → 반환 ids 중 star 인덱스에 해당하는 것마다 `motif.star` → `{"ids", "starred": [...], "cards": card_details}`.
- `POST /api/motif/star` `{"category", "id", "on": bool}` → `motif.star(category, id, off=not on)` + `{"cards": card_details}`. id는 `^M-[a-z0-9_-]+-\d{3}$`.
- 모든 라우트: category는 기존 api들과 같은 검증.
