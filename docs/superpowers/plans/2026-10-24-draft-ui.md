# 기획안 화면 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 로컬 UI의 "만들기 › 기획안"(지금 2차 안내)을 실제 화면으로: 저장된 기획안 목록·상세, 새 기획안 만들기(출처 고르기 → Claude 1회 → 대본·샷 고치기 → 저장), 모티브 카드에서 바로 이어지기.

**Architecture:** 검증·계산·저장은 기존 `scripts/draft.py`(`context`, `validate`, `planned_pacing`, `compare`, `save`)를 쓴다. UI 서버에 `scripts/ui/api_draft.py`(출처 목록, 기획안 목록·상세, 만들기 작업, 저장). 만들기는 모티브·유형화와 같은 작업 방식(끝나면 `awaiting` 미리보기, 작업 `done`, 저장 시 `job_id`로 항목을 `saved` 처리). 프런트 `pages/draft.js`.

**Tech Stack:** Python 3.11 stdlib, `scripts/claude_cli.py`, 바닐라 JS ES 모듈, pytest.

**Spec:** 채팅에서 승인된 설명(2026-10-24) — 아래 "승인된 범위"(각 Task에도 필요한 부분을 그대로 옮겨 둠). 규칙: `skills/yt-draft/SKILL.md`, 터미널 흐름: `commands/yt-draft.md`.

### 승인된 범위
- 저장된 기획안 목록(현재 카테고리): 제목, 날짜, 출처, 길이, 콘티 유무. 누르면 상세: 섹션 띠 + md 본문(대본·샷 표·아키타입 비교·준비물·내 메모) 읽기 전용, "콘티 만들기/보기"로 콘티 화면 연결.
- "새 기획안 만들기": 출처 고르기(★ 카드 → 다른 카드 → 아키타입 묶음, 없으면 모티브·유형화로 안내), 주제(선택), 목표 길이 초(선택), 버튼 → Claude 1회, 진행 표시 → 미리보기:
  제목(수정), 길이·컷 수·평균 컷, 아키타입과 섹션 비율 차이; 섹션마다 구간·라벨, 대본(수정), 샷 표(크기·앵글·길이·내용 수정, 샷 추가·삭제), 샷 길이 합 ≠ 섹션 길이면 경고(저장은 허용); 준비물(수정). "저장" → `drafts/`에 저장 후 그 기획안 상세로. "다시 만들기", "버리기".
- 모티브 카드의 "기획안 명령 복사"를 "기획안 만들기"로 바꿔 이 화면에서 그 카드가 출처로 골라진 채 열리게.
- 빼는 것: 섹션 시간·라벨 수정, 섹션 추가·삭제, 저장된 기획안 수정(md에서 직접), 삭제.

## Global Constraints
- Claude는 "만들기" 클릭 때만. 저장은 "저장" 클릭 때만(AI 출력은 확인 뒤 저장).
- 저장 형식은 CLI와 같은 `draft.save` 결과(파일명 규칙, 프런트매터, 본문 렌더). 기존 기획안 파일은 덮어쓰지 않는다(기존 `save`가 `-2`를 붙인다).
- 검증은 `draft.validate` 하나로 CLI·UI 공통. 이번에 추가하는 검증(아래 Task 1)은 CLI에도 적용되며 기존 코드 `invalid_draft`를 쓴다.
- 새 의존성 금지. 프런트 규칙(innerHTML 금지, `h()`/`fill()`, 정적 파일 `http(s)://` 금지, 페이지 계약, `alive`/`isCurrent()`, `ctx.api`, 네이티브 dialog 금지 — 확인은 인라인, 작업 재진입·handled 처리는 `pages/motif.js`와 같게).
- 사용자 대면 한국어, 식별자 영문. 커밋 Conventional Commit, Claude 서명 없음. 병렬 작업 시 커밋은 명시한 경로만.

## Review Focus
1. Claude가 허용 밖 샷 크기·라벨, 겹치는 구간, 숫자가 아닌 시간을 냄 → 1회 재시도 후 실패 메시지, 저장 없음. (Task 1)
2. 사용자가 대본에 `## 내 메모` 같은 줄, 샷 내용에 `|`·줄바꿈을 넣음 → 저장된 md의 섹션 구조와 표가 깨지지 않음. (Task 1)
3. 샷 길이에 0·음수·문자 → 저장 거부(`invalid_draft`), 입력 유지. (Task 1 + 2)
4. 같은 제목으로 두 번 저장 → 두 번째는 `-2` 파일, 첫 파일 불변. (Task 1)
5. 상세 경로에 `../`·drafts 밖·콘티 파일 → `bad_path`. (Task 1)

**`draft.validate` 보강(같은 코드 `invalid_draft`, 한국어 메시지):**
- `data`가 dict가 아니면, `sections`가 list가 아니면, 섹션·샷이 dict가 아니면, `start`/`end`가 숫자로 바뀌지 않으면(ValueError/TypeError/KeyError) → `invalid_draft`(500 금지).
- 샷 `sec`: 있으면 유한한 양수(`> 0`)여야 함.
- 한 줄로 정리(공백 접기): `title`, 샷의 `angle`·`action`, `prep` 항목. 표 칸의 `|`는 기존 render의 이스케이프 유지.
- 대본 `script`: 여러 줄 허용하되 `#`으로 시작하는 줄은 앞에 `\`를 붙여(`\#`) md 제목이 되지 않게.
- 기존 동작(정렬, `start`를 앞 섹션 `end`로 이어 붙이기, `script_only`)은 그대로 — 먼저 현재 render 결과를 고정하는 특성 테스트를 쓴다.

**Interfaces (Task 2가 씀):**
- `GET /api/draft/sources?category=<c>` → `{"stars": [카드], "cards": [카드(★ 아님)], "archetypes": [{"id","name","size","skeleton","mean_duration"}], "has_typify": bool}` — 카드는 `motif.card_details` 항목(id, title, type, type_ko, idea). 아키타입은 `motif._typify(...)["archetypes"]`(이름 포함).
- `GET /api/draft/list?category=<c>` → `{"drafts": [{"path","title","date","source","archetype","target_sec","sections":[{label,sub?,start,end}],"status","conti": path|None,"html": path|None}]}` — `drafts/*.md` 중 콘티 파일(`-conti`) 제외, 프런트매터 `category`가 같은 것, 날짜·경로 내림차순, 프런트매터가 깨진 파일은 건너뜀.
- `GET /api/draft?path=<drafts/...md>` → `{"path","title","category","date","source","archetype","target_sec","sections","pacing","hook_type","narrative_type","body": [{"heading","text"}],"conti": path|None,"html": path|None}` — 경로 검증은 `api_conti._safe_path(value, conti_file=False)` 재사용(drafts 안 .md, 콘티 파일 거부). body는 `## ` 기준 분할(`api_refs._body_parts`와 같은 규칙 — 공용으로 쓸 수 있으면 재사용).
- `POST /api/draft/run` `{"category","source","topic"?: str(≤100, 공백 정리),"target_sec"?: 5~1800 숫자}` → `{"job"}`. 출처 검증은 작업 전에 `draft.context(...)`로(없으면 `source_not_found` 그대로). `claude_cli.find_claude()` 먼저. 작업 kind `"draft"`, 항목 1개(id=category, title=출처 제목), step `"context"` → `"claude"` → `awaiting/preview/ask="save"`, preview `{"draft": 검증된 draft, "pacing": planned_pacing, "compare": compare(..)|None, "source": context["source"]}`, 작업 `done`.
  - Claude: `ask_validated([SKILLS_DIR/"yt-draft"/"SKILL.md"], payload=context (+ "target_sec" 있으면), task=DRAFT_TASK, validate=draft.validate, schema=DRAFT_SCHEMA)`. `DRAFT_TASK = "yt-draft 규칙대로 입력 출처로 기획안 draft JSON을 만드세요. target_sec가 있으면 그 길이에 맞추세요."` `DRAFT_SCHEMA`: object(title, topic, source, archetype, hook_type, narrative_type, sections[{label, sub, start, end, script, shots[{size, angle, sec, action}]}], prep[]); required title, hook_type, narrative_type, sections. 아키타입 찾기는 `draft.save`와 같은 방식(모듈 함수로 뽑아 공용).
- `POST /api/draft/save` `{"category","draft": {...},"job_id"?}` → 검증 → mkstemp(`workspace/tmp/draft_ui_*.json`, finally 삭제) → `draft.save` → `{"path","pacing","compare"}`; 성공 후 `job_id`가 같은 카테고리의 draft 작업이고 항목이 awaiting이면 `state="saved", ask=None`.
- 모든 라우트 category 검증은 기존 api들과 같은 방식.
