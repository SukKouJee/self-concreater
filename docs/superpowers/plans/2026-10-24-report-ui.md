# 리포트 화면 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 로컬 UI "분석 › 리포트"(지금 2차 안내)를 실제 화면으로: ① 카테고리 리포트 만들기·보기 ② 주간 회고(숫자 → Claude 회고 1회 → 고쳐 저장 → 프로필 변경 제안 골라 반영).

**Architecture:** 기존 `scripts/report.py`(`build`)와 `scripts/mission.py`(`week`, `review_save`, `profile_update`)를 쓴다. 회고 검증을 `mission.validate_review(data)`로 뽑아 Claude 응답 검증과 `review_save`가 같이 쓴다. UI 서버 `scripts/ui/api_report.py`, 프런트 `pages/report.js`(탭 2개).

**Spec:** 채팅에서 승인(2026-10-24) — 아래 "승인된 범위". 규칙: `skills/yt-mission/SKILL.md` 6절, 터미널: `commands/yt-review.md`.

### 승인된 범위
- ① 카테고리 리포트: "리포트 만들기"(Claude 없음, 현재 카테고리) → `reports/<카테고리>-<날짜>.html`. 만든 리포트 목록(날짜별), 고르면 화면 안에서 보기 + "새 탭에서 열기".
- ② 주간 회고: 주 고르기(이번 주 기본, 지난 회고가 있는 주 목록). 이번 주 숫자 바로(Claude 없음): 미션 완료율, 종류·난이도 분포, 건너뛴 사유, 새 모티브 카드 수, 진단 갭. "회고 쓰기"(Claude 1회) → 요약·반복된 약점·다음 주 방향·프로필 변경 제안(모두 고칠 수 있음) → "저장" → `reviews/<주>.md`(`## 내 메모` 유지). 프로필 반영: 제안마다 체크박스, 체크한 섹션만 "프로필에 반영" → `profile.md`(바꾸기 전 값과 바꿀 값을 나란히). 프로필이 없으면 숨기고 `/yt-coach:yt-init` 안내. 저장된 회고는 마크다운으로.
- 내 결정: 리포트 HTML은 화면 안 프레임에서 스크립트 실행을 막는다(`sandbox`, 리포트는 스크립트 없는 그림·표). 화면에서는 회고도 "저장"을 눌러야 기록(AI 출력 확인 후 저장 원칙).
- 빼는 것: 리포트 디자인 변경, 여러 카테고리 한꺼번에.

## Global Constraints (각 Task 지시에 그대로 포함)
- Claude는 "회고 쓰기"(와 "다시 쓰기") 클릭 때만. 회고 저장·프로필 반영은 각각 버튼 클릭 때만, 프로필은 체크한 섹션만.
- `reviews/<주>.md`·`profile.md`의 `## 내 메모`는 절대 덮어쓰지 않는다 — 지금 `review_save`는 파일을 통째로 다시 써서 메모가 사라진다(고친다: 기존 메모를 옮겨 붙임). `profile.md`는 `replace_section`으로 바뀐 섹션만(기존대로) — 메모 섹션 이름은 바꿀 수 없다.
- 쓰기는 `refstore.write_atomic` + 모듈 lock. 줄바꿈 방식(CRLF/LF) 유지.
- 프로필 변경 값 검증: 기존 `profile_update` 규칙(`PROFILE_SECTIONS`, `성장 단계` ∈ STAGES). 값에 `## ` 줄이 섞이면 `refstore.escape_headings`로 막는다(섹션 구조 보호).
- 리포트 미리보기: `<iframe sandbox="" src="/files/reports/…">`(스크립트·폼·팝업 불가). `/files/`는 `reports/`를 이미 허용. 리포트 파일 이름은 `<카테고리>-YYYY-MM-DD.html`만 목록에.
- 새 의존성 금지. 프런트: innerHTML 금지, `h()`/`fill()`, 정적 파일 `http(s)://` 금지, 네이티브 dialog 금지(인라인 확인), 페이지 계약·`alive`/`isCurrent()`·`ctx.api`, 작업 재진입·handled·`job_id`·aborted 처리는 `pages/motif.js` 방식, md 본문은 `static/md.js` `renderMarkdown`.
- 사용자 대면 한국어, 식별자 영문. 커밋 Conventional Commit, Claude 서명 없음. 병렬 작업 시 커밋은 명시한 경로만.
- **프로세스를 이미지 이름으로 끄지 않는다**(`taskkill /IM python.exe`/`node.exe`, `Stop-Process -Name`, `pkill` 금지 — CLAUDE.md). 직접 띄운 PID만.

## Review Focus
1. 같은 주 회고를 다시 저장 → `## 내 메모` 유지, `approved` 등 프런트매터 갱신 정상.
2. 제안 중 일부만 체크해 반영 → 체크한 섹션만 바뀌고 나머지·메모 불변, 회고 프런트매터 `approved`는 반영한 섹션 목록으로 기록.
3. 미션이 0개인 주 → 숫자 영역은 "기록 없음", 회고 쓰기는 가능(레퍼런스·모티브 현황 위주) 또는 안내.
4. 유형화 결과가 없는 카테고리 → 리포트 만들기가 깨지지 않음(기존 build 동작 확인, 오류면 안내).
5. 주 형식 `YYYY-Www` 검증, 존재하지 않는 주(W54 등) → `bad_request`.

**Files:** Modify `scripts/mission.py`(`validate_review`, `review_save` 메모 보존·원자 쓰기, `profile_update` 원자 쓰기·헤딩 이스케이프·CRLF 유지), `scripts/ui/jobs.py`(`SINGLE_KINDS["review"] = "이미 회고를 쓰는 중입니다"`); Create `scripts/ui/api_report.py`; Modify `scripts/ui/server.py`(`ROUTE_MODULES`); Test `tests/test_mission.py`, `tests/test_report.py`(필요 시), `tests/test_ui_report.py`.

**Interfaces (Task 2가 씀):**
- `mission.validate_review(data) -> dict` — 요약 필수(기존 메시지 `invalid_review` "summary가 비어 있습니다" 유지), `repeated_weakness`/`next_week` 문자열 목록(한 줄 정리), `profile_proposal` dict(키 ∈ PROFILE_SECTIONS, `성장 단계` ∈ STAGES, 값 문자열) — 모양 오류 `invalid_review`. `review_save`가 이것을 쓴다.
- `GET /api/report/list?category=` → `{"category","reports": [{"path","date","url"}] (날짜 내림차순), "has_typify": bool}`.
- `POST /api/report/build` `{"category"}` → `report.build(category)` 결과 + `url`(퍼센트 인코딩) — 동기(빠름). 실패는 ScriptError 그대로.
- `GET /api/review/weeks` → `{"current": "YYYY-Www","weeks": [{"week","range","saved": bool}]}` — 이번 주 + `reviews/*.md`가 있는 주(내림차순, 중복 없음).
- `GET /api/review?week=` → `{"week","range","stats": mission.week(...) 중 화면용(missions, difficulty, skip_reasons, kinds, cards_created, diagnosis_gaps 개수·목록, refs),"saved": {"fm","body":[{heading,text}]}|None,"profile": {"exists": bool,"sections": {이름: 현재 텍스트}}}`.
- `POST /api/review/write` `{"week"}` → `{"job"}`: `find_claude()` 먼저. 작업 kind `"review"`, 항목 id = week, step `"stats"` → `"claude"` → awaiting preview `{"review": 검증된 회고, "week"}`. Claude: `ask_validated([SKILLS_DIR/"yt-mission"/"SKILL.md"], payload=mission.week(week), task=REVIEW_TASK, validate=mission.validate_review, schema=REVIEW_SCHEMA)`; `REVIEW_TASK = "yt-mission 규칙 6절대로 입력 주의 회고 JSON(summary, repeated_weakness, next_week, profile_proposal)을 만드세요. 근거가 약하면 profile_proposal은 비워 두세요."`.
- `POST /api/review/save` `{"week","review","job_id"?}` → mkstemp(`workspace/tmp/review_*.json`, finally 삭제) → `mission.review_save` → 결과 + `saved`(위 GET 모양). job 항목 awaiting이면 `saved`.
- `POST /api/review/apply` `{"week","sections": {이름: 텍스트}}` → 비어 있으면 `bad_request`; `mission.profile_update`(mkstemp 경유) → 회고 프런트매터 `approved`를 반영한 섹션 이름 목록으로 갱신(`refstore.update_frontmatter`) → `{"updated", "sections", "profile": {...}}`.
- `week` 검증: `YYYY-Www`이고 `date.fromisocalendar`로 실제 존재 → 아니면 `bad_request`.
