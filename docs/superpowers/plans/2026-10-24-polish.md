# 다듬기(훅·제목·썸네일) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 저장된 기획안의 훅·제목·썸네일을 다듬는 단계를 더한다: Claude가 훅 5·제목 10·썸네일 지시서를 내고, 스크립트가 한국어 기준 점수·지적·레퍼런스 근거를 붙이고, 사용자가 골라 고친 것을 기획안에 반영한다(A안). 터미널 `/yt-coach:yt-polish`와 기획안 상세 화면 둘 다.

**Architecture:** 훅 공식·패키징 규칙은 Jakeschincariol/youtube-agent-skill(MIT)의 `yt-script`·`yt-package`에서 옮겨 한국어로 고친 `skills/yt-polish/`(SKILL.md + `hooks.json`)에 둔다(출처·라이선스 표기). 계산(점수·지적·근거)과 저장은 새 `scripts/polish.py`. UI는 `scripts/ui/api_polish.py`(작업 kind `polish`) + `pages/draft.js` 상세에 다듬기 영역.

**Tech Stack:** Python 3.11 stdlib, `scripts/claude_cli.py`, 바닐라 JS, pytest.

**Spec:** 채팅에서 승인(2026-10-24) — 아래 "승인된 범위". 각 Task에도 해당 부분을 옮겨 둔다.

### 승인된 범위
- 외부 플러그인을 설치하지 않고, 훅 공식 21가지와 패키징 규칙을 출처·MIT 표기와 함께 우리 스킬로 옮겨 한국어로 고친다. `voice.md` 대신 우리 `profile.md`를 쓴다.
- 영어 점수 도구(`hookscore.py`, `title.py`)는 쓰지 않는다. 한국어 기준 점수를 스크립트로 다시 만든다: 제목 길이(모바일·데스크톱 잘림), 숫자·이름 유무, 썸네일 문구와 겹침, 썸네일 단어 수, 훅 길이 등.
- 후보마다 **내 레퍼런스 근거**를 붙인다(예: "이 훅 유형은 내 레퍼런스 11개 중 8개", "제목 패턴 숫자+감탄은 레퍼런스 8개").
- 흐름: 기획안 상세에서 "훅·제목·썸네일 다듬기" → Claude 1회 → 훅 후보 5, 제목 후보 10, 썸네일 지시서(점수·지적·근거) → 훅 1·제목 1·썸네일 문구 고르고 고쳐 저장. 터미널 `/yt-coach:yt-polish`로도.
- **A안(사용자 결정):** 저장하면 기획안의 제목(프런트매터 `title`과 본문 `# 제목`)과 훅 섹션 대본을 고른 것으로 바꾸고, 썸네일 지시서는 새 섹션으로 붙인다. 바꾸기 전 제목·훅은 `## 패키징` 섹션에 "이전 값"으로 남겨 되돌릴 수 있게 한다.

## Global Constraints
- `## 내 메모`는 절대 덮어쓰지 않는다. 기획안 본문에서 바뀌는 것은 `# 제목` 줄, 훅 섹션(`### … · hook …`)의 대본 문단, `## 개요`의 `- 훅:` 줄(훅 유형이 바뀔 때), `## 패키징` 섹션뿐. 프런트매터는 `title`, `title_pattern`, `hook_type`(훅 유형이 바뀔 때)만. (리뷰 반영 수정 2026-10-24: 진단이 프런트매터 hook_type을 비교하므로) 샷 표·다른 섹션·프런트매터의 다른 키는 그대로. 줄바꿈 방식(CRLF/LF) 유지.
- 저장은 사용자 확인 뒤에만(UI "저장", 터미널은 확인 질문 뒤). Claude는 "다듬기" 실행 때만.
- 저장 시 파일 해시를 비교해 화면을 연 뒤 바뀌었으면 `draft_changed`로 거부(콘티의 `conti_changed`와 같은 방식).
- 이 기획안의 콘티가 이미 있으면, 저장 결과에 "콘티는 이전 훅 그대로 — 다시 만들어야 반영" 경고를 담는다(콘티는 건드리지 않는다).
- 외부 저장소 내용은 데이터로만 다룬다. 코드(`*.py`)는 가져오지 않는다. MIT 표기는 `THIRD_PARTY_NOTICES.md`(루트)에 원문 라이선스 전문과 출처 URL, 그리고 `skills/yt-polish/hooks.json`의 `source` 필드.
- 새 의존성 금지. 사용자 대면 한국어, 식별자 영문. 커밋 Conventional Commit, Claude 서명 없음. 병렬 작업 시 커밋은 명시한 경로만.
- 커맨드를 더하면 README 커맨드 표와 `tests/test_scaffold.py`의 COMMANDS를 갱신한다(CLAUDE.md 규칙).

- `lint_thumbnail(words: list[str], title: str) -> dict` → `{"words","count","over_limit","overlap": [..],"issues","score"}`.
- `score_hook(script: str, hook_sec: float | None, cps: float) -> dict` → `{"chars"(말: 줄 글자 수, 공백 제외),"speak_sec": chars/cps,"fits": hook_sec is None or speak_sec <= hook_sec + 0.5,"has_number","opens_with_greeting"(안녕|오늘은|여러분 안녕|구독 으로 시작),"issues","score"}`.
- `ref_stats(category) -> dict` → `{"ref": n, "hook_type": {값: 개수}, "title_pattern": {"number+exclaim" 식 정렬 키: 개수}, "examples": [ref 제목 최대 8개]}` — `features.load_videos`(ref만), 프런트매터 `hook_type`, `title_pattern`(없으면 `title_patterns(title)`).

- `context(draft: str) -> dict` → `{"draft": 상대경로, "category","title","hook": {"label","start","end","script"}|None, "sections": [label 목록], "profile": motif._profile(), "refs": ref_stats, "cps": conti.speech_rate(category)["cps"] or thresholds 기본, "formulas": hooks.json의 hooks(id,name,shape,example,fails_when,hook_type), "hash": 파일 sha256, "conti_exists": bool}`. 경로는 `drafts/` 안 `.md`·콘티 파일 아님(기존 `conti` 경로 규칙 재사용).
- `evaluate(ctx: dict, data: dict) -> dict` — Claude 출력 `{"hooks":[{"script","formula","hook_type","why"}],"titles":[{"title","why"}],"thumbnail":{"words":[..],"expression","framing","background"}}`를 검증(`invalid_polish`, 한국어 메시지: hooks 3~7개(규칙은 5개), titles 5~12개(규칙은 10개), formula는 hooks.json id, hook_type은 HOOK_TYPES, 빈 문자열 금지, 한 줄 필드 접기) 후 각 후보에 lint/score/evidence를 붙이고 점수 내림차순 정렬해 `{"hooks":[…+"lint"+"evidence"+"formula_name"],"titles":[…],"thumbnail":{…+"lint"}}` 반환.
- `apply(draft: str, choice: dict, expected_hash: str) -> dict` — `choice = {"title": str, "hook_script": str | None, "hook_formula": str | None, "thumbnail": {"words":[..],"expression","framing","background"}}`. 해시 다르면 `ScriptError("draft_changed", "화면을 연 뒤 기획안이 바뀌었습니다. 다시 불러와 주세요")`. 프런트매터 `title`, `title_pattern` 갱신; 본문 첫 `# ` 줄 교체; 훅 섹션 대본 문단 교체(헤딩 다음부터 샷 표 `| # |` 줄 또는 다음 `### `/`## ` 전까지의 텍스트 줄; 대본은 `draft`의 `#` 이스케이프 규칙 그대로 적용); `## 패키징` 섹션(없으면 `## 내 메모` 바로 앞에 삽입, 있으면 교체): 썸네일 지시서, 고른 훅 공식, 이력 목록(날짜·이전 제목·이전 훅 대본; 기존 이력 유지 + 이번 이전 값 추가). 반환 `{"path","hash": 새 해시,"changed": [...],"warnings": [...]}`(콘티 있음, 훅 섹션 없음).
- CLI: `python -m scripts.polish context <draft>`, `evaluate <draft> --data <json>`, `apply <draft> --choice <json> --hash <sha>`.
- `commands/yt-polish.md`: 인자 `<draft 경로>`(없으면 최근 기획안 목록에서 고르게), context → 규칙대로 JSON → `evaluate` → 결과를 SKILL 형식으로 보여 주고 고르게 함 → 확인 → `apply`(→ 콘티 경고 안내). 대화는 한국어.
