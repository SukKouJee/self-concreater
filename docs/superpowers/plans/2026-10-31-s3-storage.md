# S3 저장소 인터페이스 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 작업 폴더 경로를 직접 다루는 코드를 저장소 인터페이스(DocStore·ObjectStore·SharedCache·Scratch·Trash)와 그 파일 구현(FileStore) 뒤로 옮긴다. 로컬판 파일·출력은 바이트 단위로 그대로.

**Architecture:** `docs/superpowers/specs/2026-10-31-s3-storage-design.md`(이하 "S3 설계")가 이 계획의 본문이다. 키 = 작업 폴더 상대 POSIX 경로(ADR-1), 저장소는 바이트 계층(ADR-2), 키 생성은 `scripts/keys.py`, 경로 조립은 `scripts/filestore.py`, 모듈은 `ctx.here().store/objects/shared/scratch/trash`만 쓴다.

**Tech Stack:** Python 3.11 표준 라이브러리, pytest.

**Spec:** `docs/superpowers/specs/2026-10-31-s3-storage-design.md` (상위: `2026-10-31-multiuser-server-design.md` §2·§6 S3)

## Global Constraints
- 로컬판의 작업 폴더 구조·파일 바이트·CLI JSON·UI API JSON은 바뀌지 않는다(S3 설계 §0; 예외는 원자적 쓰기로의 전환뿐, 최종 바이트 동일).
- 각 작업은 **먼저 바뀌기 전 코드에서 통과하는 특성 테스트를 커밋**하고, 그다음 이전 커밋을 한다(S3 설계 §6 공통 조건).
- `write_text` 기본 줄바꿈을 쓰던 곳은 `refstore.text_bytes`로 같은 바이트를 만든다(S3 설계 §7-1). 그 밖의 줄바꿈 규칙은 손대지 않는다.
- 경로 문자열이 저장·노출되는 곳(프런트매터, cuts json, API JSON, `/files` URL, `abs_*` 출력, 오류 메시지 접두사)은 지금과 같은 문자열(S3 설계 §7-3·4·5).
- resolve 기반 탈출 검사는 같은 강도로 유지하고 우회 회귀 테스트를 남긴다(§7-6).
- md 본문·`## 내 메모` 보존. 새 의존성 없음. 커밋 제목 Conventional Commit, AI 서명 금지.
- 테스트: 작업마다 건드린 모듈의 테스트 + 특성 테스트. **전체 `pytest tests/`는 컨트롤러가 작업 3·7·12·15 뒤에 돌린다**(15분, 메모리 부담 때문에 구현자는 돌리지 않는다).
- `python -m scripts.count_work_root`의 `all` 합계는 작업마다 줄거나 같다(작업 1 제외).

## Review Focus
- Windows에서 CRLF로 쓰이던 JSON·HTML이 LF로 바뀌는 회귀(특성 테스트가 실제 바이트를 비교해야 함).
- `list`/`folders` 순서가 `sorted(glob)`와 달라져 화면 목록·최근 항목 순서가 바뀌는 회귀(대소문자 섞인 이름).
- 테스트가 `YT_COACH_HOME`만 바꿔 가며 같은 프로세스에서 여러 작업 폴더를 쓰는데 저장소가 캐시돼 root가 새는 문제(ADR-7).
- `..`·절대 경로·심볼릭 링크로 작업 폴더 밖을 가리키는 키/인자.
- 두 스레드가 같은 파일을 동시에 원자적으로 쓸 때 임시 파일 충돌(§7-13).
