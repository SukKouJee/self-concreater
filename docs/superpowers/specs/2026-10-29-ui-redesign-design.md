# yt-coach UI 개선 — 설계

출처: 사용자 지시서(2026-10-29, 아래 1~6절 원문 그대로)와 Claude Design 캔버스 "yt-coach UI 개선 시안"(https://claude.ai/artifact/DSSo87bVsV4ktzdCk6h1bE). 시안 4장의 원본(.dc.html)은 `docs/ui-mockups/`에 있다(정적 마크업과 예시 데이터 — 구현의 배치·크기·색 기준). 7절은 구현하며 정한 것(내 판단).

## 0. 작업 규칙
- **먼저 현재 프론트엔드 구조를 파악한다**(프레임워크, 라우터, 컴포넌트·스타일 위치, API 호출부). 파악 결과를 3~5줄로 보고한 뒤 Phase 1을 시작한다. (보고 완료, 7절 참고)
- **백엔드 API·데이터 스키마·md 파일 포맷은 바꾸지 않는다.** UI가 필요로 하는 값이 API에 없으면 구현하지 말고 목록으로 보고한다.
- 기존 라우트 URL은 리다이렉트로 유지한다(북마크·링크 보존).
- Phase 단위로 커밋하고, 각 Phase 끝에 데스크톱(1280px)과 폰(390px) 폭에서 화면을 확인한다.
- 문구는 한국어, 초보 크리에이터 기준의 쉬운 말.

## 1. 핵심 원칙
1. **영상(프로젝트) 한 편 중심.** 기획안·콘티·촬영·진단은 영상 페이지 안의 탭이다. 메뉴를 옮겨 다니지 않는다.
2. **단순하게.** 한 화면에 주요 행동 버튼은 1개. 보조 행동은 작은 버튼이나 텍스트 링크. 큰 배너·과한 여백 금지.
3. **고르는 화면은 훑기 좋게.** 카드에는 제목·한 줄·태그·근거 썸네일만. 상세는 옆 패널(데스크톱) 또는 바텀시트(폰).
4. **기계 용어 숨기기.** 로컬 경로, 파일명(`*.md`, `*-conti.html`), 터미널 커맨드 안내를 화면에서 없앤다. 영상 제목·날짜로 표시한다.
5. **Claude 작업 상태는 헤더 한곳.** "Claude가 ○○ 만드는 중 · 18초" 상태 칩. 끝나면 토스트로 알리고 결과로 이동 링크.
6. **폰 우선 고려.** 390px에서 깨지지 않을 것. 촬영 현장에서 쓰는 촬영 모드가 있다.

## 2. 정보 구조 (메뉴)
| 그룹 | 항목 | 기존 라우트 |
|---|---|---|
| 영감 | 레퍼런스 (개수), 유형 (개수), 모티브 (개수) | `#/refs`, `#/library`는 레퍼런스 안 탭, `#/typify`, `#/motif` |
| 내 영상 | 진행 중 영상 목록(제목 + 진행 막대 + 현재 단계), `+ 새 영상 시작` | `#/draft`, `#/conti`, `#/diagnose` → 영상 작업 공간으로 통합 |
| 성장 | 오늘 미션, 주간 리포트 | `#/mission`, `#/report` |

- 새 라우트: `#/video/:id` (탭: `plan` 기획안 / `conti` 콘티 / `shoot` 촬영 체크 / `diagnose` 진단), `#/video/:id/shoot` (촬영 모드)
- 영상 id는 draft 파일 slug를 그대로 쓴다(새 저장 구조 만들지 않음).
- 데스크톱: 왼쪽 사이드바(220~260px, 흰 배경 계열, 검은 사이드바 폐지). 폰: 하단 탭 4개(홈 / 영감 / 내 영상 / 미션).
- 헤더: 로고, 카테고리 선택, Claude 작업 상태 칩, 도움말(작은 버튼). **로컬 경로 표시 제거.** "서버 끄기"는 도움말 메뉴 안으로.

## 4. 화면별 명세

### 4.1 홈 `#/home`
- 데스크톱: 다음 할 일(한 줄 카드 + 작은 주요 버튼) → 만들고 있는 영상(최대 3, 더보기) → 오늘 미션 → 최근 결과물(파일명 대신 "영상 제목 · 콘티 · 10월 29일").
- 폰: 다음 할 일 카드(어두운 카드, "촬영 모드 시작" 큰 버튼) → 오늘 미션 → 만들고 있는 영상 3개(썸네일 + 6칸 단계 점 + 현재 단계).

### 4.2 영상 작업 공간 `#/video/:id` (시안: 데스크톱 · 영상 작업 공간)
위에서 아래로:
1. 브레드크럼 `내 영상 › 짧은 제목`
2. 제목(30px, 굵게, 왼쪽 빨간 세로선) + 메타 줄: 시작일 · 목표 길이 · 출처 모티브 칩 · 유형 칩
3. **진행 바 한 줄**(흰 카드): 6단계 막대(기획안 / 다듬기 / 콘티 / 촬영 / 편집 / 진단, 라벨에 ✓ – ●) + 오른쪽에 `촬영 0 / 6컷`, `폰 촬영 모드`(빨강 작은 버튼), `다 찍음`(테두리 작은 버튼). 현재 단계에 따라 오른쪽 행동이 바뀐다.
4. 탭 줄(밑줄 탭) + 오른쪽에 요약(`6컷 · 15:00 · 평균 컷 3.0초`)과 텍스트 링크 `인쇄`, `다시 만들기`
5. (콘티 탭) 도구 줄: 컷 검색(작게), 구간 필터 칩(전체 / 도입 / 본론 / 마무리), 오른쪽 보기 전환(카드 / 리스트)
6. (콘티 탭) 컷 카드 그리드 `repeat(auto-fill, minmax(210px, 1fr))`, 카드: 프레임 영역 112px(레퍼런스 프레임 이미지가 있으면 표시, 없으면 샷 설명 텍스트) + 좌상단 `01 · 0:00–0:10` + 섹션 태그 + 행동(굵게) + 대사(따옴표) + `참고 · 근거 모티브/영상`
- 기획안 탭: 기존 기획안 md 렌더링 + 편집. 진단 탭: 기존 진단 화면을 이 영상 기준으로.
- 기존 "스토리보드 HTML" 버튼 기능은 `인쇄`로 연결.

### 4.3 모티브 `#/motif` (시안: 데스크톱 · 모티브 고르기)
- 상단: 제목 + 한 줄 설명, 오른쪽에 주제 입력 + `새 카드 뽑기 · 약 30초`(클릭 시 헤더 상태 칩으로 진행 표시, 화면은 계속 사용 가능)
- 필터 칩: 전체 / ★ / 흐름 / 기법 / 각도 / 조합 (개수 포함)
- 카드 그리드 `minmax(230px, 1fr)`: 종류 태그, ☆/★ 토글, 제목, **한 줄 요약**, 근거 영상 썸네일 3개 + `근거 영상 N`. 본문 전문·단계 목록은 카드에 넣지 않는다.
- 카드 클릭 → 오른쪽 상세 패널(데스크톱, 380px) / 바텀시트(폰): 설명, "이렇게 찍어 보세요" 단계, 근거 영상(썸네일 + 제목 링크), 이 카드로 만든 영상, 주요 버튼 `이 카드로 새 영상 시작`
- "한 줄 요약" 필드가 데이터에 없으면 본문 첫 문장을 잘라 쓰고, 별도 필드가 필요하면 보고만 한다.
- "터미널 /yt-coach:yt-inspire에서…" 안내 문구 제거.

### 4.4 촬영 모드 `#/video/:id/shoot` (시안: 폰 · 촬영 모드) — 폰 전용 우선
- 어두운 전체 화면. 상단: 닫기(44px), "촬영 모드 / 짧은 제목", 오른쪽 `3 / 6`
- 컷 진행 막대(완료 초록, 현재 흰색, 남은 것 회색)
- 프레임 영역(216px): 섹션 태그, 타임코드, 샷 설명, 찍은 컷은 `찍음 ✓` 배지
- 행동(22px 굵게), 대사 박스(18px), 촬영 팁 2개
- 하단: `‹` / 큰 `찍었어요 ✓`(찍은 뒤엔 `다음 컷으로`, 마지막엔 `전부 찍었어요!`) / `›`
- 체크 상태는 서버에 저장(기존 "촬영함 체크" API 재사용). API가 컷 단위를 지원하지 않으면 우선 브라우저 저장(try/catch)으로 하고 보고한다.
- 화면 꺼짐 방지(Wake Lock API, 지원 시)

### 4.5 레퍼런스·유형·리포트·미션
- 레퍼런스: 기존 썸네일 그리드 유지. 헤더 톤·버튼 크기·칩 스타일만 토큰에 맞춘다. 공용 라이브러리는 탭으로.
- 유형: 축별 판정 표와 아키타입 카드 유지, 토큰 적용.
- 미션·리포트: 토큰 적용, 파일명 노출 제거.

## 5. 진행 순서
| Phase | 내용 | 완료 조건 |
|---|---|---|
| 1 | 토큰·공통 컴포넌트(버튼 S/M, 칩, 카드, 탭, 상태 칩), 새 헤더·사이드바·폰 하단 탭, 경로/파일명 노출 제거 | 모든 화면이 새 셸로 뜨고 390px에서 가로 스크롤 없음 |
| 2 | 영상 작업 공간 `#/video/:id` + 탭 통합, 기존 라우트 리다이렉트 | 홈의 진행 중 영상 클릭 → 작업 공간, 기획안·콘티·진단 탭 전환 |
| 3 | 콘티 카드 그리드 + 도구 줄 | 기존 콘티 데이터로 컷 카드가 모두 보임 |
| 4 | 모티브 카드 + 상세 패널/바텀시트, "새 영상 시작" 연결 | 카드 선택 → 상세 → 새 영상 생성 흐름 동작 |
| 5 | 촬영 모드 | 폰 폭에서 컷 넘기기·체크·저장 동작 |
| 6 | 홈 재구성, Claude 작업 상태 칩·토스트 | 장시간 작업 중 다른 화면 이동 가능, 완료 알림 |
| 7 | 나머지 화면 토큰 적용, 정리 | 전 화면 시각 점검 |

## 6. 하지 않을 것
- 백엔드·스키마·md 포맷 변경, 새 저장소 도입
- 새 UI 라이브러리 대량 도입(필요하면 먼저 제안)
- 이모지 아이콘(★☆ 별표 제외), 그라데이션 장식

## 7. 구현 결정 (내 판단)

현재 구조(0절 보고): 프레임워크 없는 ES 모듈, `dom.js`의 `h()`로 DOM 생성, 해시 라우터·메뉴는 `scripts/ui/static/app.js`, 화면은 `pages/*.js` 15개(콘티 편집기 `pages/conti.js` 2,405줄), 스타일은 `app.css` 한 파일(shadcn zinc 토큰, 검은 사이드바), 서버 호출은 `api.js`의 `api()`, 긴 Claude 작업은 `/api/jobs/current?kind=` 폴링.

- **폰트**: 외부 URL 금지 규칙(정적 파일에 `https?://` 금지 테스트, 로컬 전용) 때문에 Google Fonts를 불러오지 않는다. `font-family: 'Noto Sans KR', 'Malgun Gothic', 'Apple SD Gothic Neo', system-ui, sans-serif`(설치돼 있으면 Noto), 타임코드 `'JetBrains Mono', ui-monospace, Consolas, monospace`. 폰트 파일을 저장소에 넣지 않는다(라이브러리 대량 도입 금지와 같은 취지).
- **토큰**: 3절 값을 `app.css`의 기존 토큰 자리에 넣는다(기존 이름을 쓰는 곳이 많으므로 기존 이름은 새 값으로 다시 가리키고, 3절 이름을 추가). 색 대비 4.5:1을 지킨다(시안 값 그대로면 통과).
- **다크 모드**: 지시서대로 촬영 모드만 어두운 배경. 지금 있는 앱 전체 다크 테마(`prefers-color-scheme`)는 이번에 끈다(라이트 고정). (지시서 "다크 모드: 촬영 모드만" 해석)
- **영상 id**: draft 파일 이름에서 `.md`를 뗀 것(`drafts/` 아래 상대 경로, 하위 폴더면 `/`를 포함한 채 인코딩). 서버는 지금처럼 `path`로 받는다.
- **6단계 진행**: 기존 API로 계산한다 — 기획안(draft 있음) / 다듬기(polish 결과가 있는지 기존 API로 확인, 없으면 "–" 건너뜀) / 콘티(conti 있음) / 촬영(draft `filmed_at`) / 편집(편집본 경로 또는 내 영상 진단 대상이 있으면) / 진단(이 영상에 진단 결과). API로 알 수 없는 단계는 "–"로 두고 보고 목록에 적는다.
- **컷별 촬영 체크**: 서버에 컷 단위 체크 API가 없다(`/api/drafts/filmed`는 기획안 단위). 브라우저 저장(`localStorage`, 키 `ytc.shoot.<영상 id>`, try/catch)으로 하고, `전부 찍었어요!`를 누르면 기존 `/api/drafts/filmed`로 기획안 단위 "다 찍음"을 저장한다. 보고 목록 1번.
- **모티브 한 줄 요약**: 별도 필드가 없으면 본문 첫 문장(최대 60자). 보고 목록 2번.
- **Claude 작업 상태 칩**: 기존 `/api/jobs/current?kind=` 폴링을 헤더 한곳에 모은다(모든 kind). 서버에 "모든 작업" 조회가 없으면 kind별로 묻는다(새 API 금지).
- **장면 단위 콘티와의 관계**: 별도 브랜치(`feat/scene-conti`)에서 콘티의 서버 쪽(장면 합치기, 사진 설명, 장면별 사진 고르기)을 만들고 있다. 그 작업의 화면 부분은 이 개편의 Phase 3(콘티 카드 그리드)에 합친다: 카드 프레임 영역에 장면 사진, `참고 · <설명>` / `구도만 참고 · <설명>`, 합치기·사진 설명 만들기·사진 다시 고르기 버튼. Phase 3은 `feat/scene-conti`가 이 브랜치에 합쳐진 뒤에 시작한다. 이것은 지시서의 "백엔드 변경 금지"에 해당하지 않는다(사용자가 따로 승인한 작업).
- **콘티 편집 기능 보존**: 지금 콘티 편집기의 기능(대사·가이드 고치기, 대안, 컷 넣기/빼기/옮기기, 길이, 이력, 촬영 영상 영역, SRT·자막 영상)은 모두 콘티 탭 안에 남긴다. 카드 그리드는 보는 방식이고, 카드를 누르면 지금의 편집 패널이 열린다.
- **보고 목록**(구현하지 않고 사용자에게 알릴 것): 컷별 촬영 체크 API, 모티브 한 줄 요약 필드, 6단계 중 API로 알 수 없는 단계, 근거 영상 썸네일이 모티브 API에 없으면 그것.
- **촬영 체크 탭 키**: 영상 작업 공간의 탭 키는 `plan` / `conti` / `check`(촬영 체크) / `diagnose`. `#/video/:id/shoot`은 폰 촬영 모드 라우트라 탭 키로 쓰지 않는다(2절 `shoot` 탭 표기는 `check`로 읽는다). 탭 없이 `#/video/:id`로 열면 촬영을 마친 영상은 진단, 나머지는 콘티 탭.
- **떠나기 전 확인**: 콘티 컷 편집·다듬기 입력처럼 저장하지 않은 입력이 있으면 탭 이동·다른 화면 이동·카테고리 바꾸기 전에 화면 안에서 묻는다(`버리고 이동` / `계속 편집`, 브라우저 대화상자 없음). 머무르면 주소와 카테고리는 영상 그대로 돌아온다.

### 보고 목록 (API 공백)
Phase 1–2에서 확인한, 지금 API로는 얻을 수 없어 구현하지 않았거나 대신한 값이다(백엔드 변경 금지). `docs/ui-mockups/REPORT.md` 대신 이 목록을 쓴다.
1. **컷별 촬영 체크**: 컷 단위 저장 API가 없다(`/api/drafts/filmed`는 기획안 단위). 진행 카드의 `촬영 0 / N컷`은 기획안의 `filmed_at`으로 0 또는 전부만 센다. Phase 5에서 브라우저 저장으로 보완.
2. **"편집" 단계**: 편집본 API가 없어 자막 영상(`captions`)이 있으면 완료로 본다.
3. **6단계 중 알 수 없는 단계**: `/api/status`를 못 받으면 촬영·편집·진단 단계는 `–`, 오른쪽 행동은 비운다(완료로 표시하지 않음).
4. **짧은 제목**: 필드가 없어 브레드크럼은 제목을 24자에서 자른다.
5. **모티브 칩**: 기획안 `source`가 모티브 카드 id이고 `/api/motif`가 그 카드를 아직 가질 때만 나온다. 아키타입 출처("A1")면 유형 칩만.
6. **모티브 한 줄 요약**: 필드가 없으면 본문 첫 문장(4.3, Phase 4에서 확인).
7. **근거 영상 썸네일**: 모티브 API에 없으면 보고(Phase 4에서 확인).
8. **개수만 주는 API 없음**: 사이드바 숫자(레퍼런스·유형·모티브)를 위해 화면을 옮길 때마다 `/api/status`·`/api/typify`·`/api/motif`(카드 전체)를 읽는다.
9. **영상 한 편 읽기**: 처음 열 때 `/api/draft`·`/api/status`·`/api/motif`·`/api/typify`·`/api/conti`를 읽는다(탭 이동은 `/api/status`만, 촬영 체크 탭과 콘티 탭을 떠날 때 `/api/conti`도). 한 번에 주는 API가 없다.
10. **최근 결과물 제목**: `/api/status.recent`는 파일 경로만 준다. 같은 응답의 영상 제목으로 채우고, 다른 카테고리 기획안은 파일 이름에서 날짜·확장자·대시를 뺀다.
11. **도움말 챗봇 메뉴**: `api_help.MENU`(백엔드)는 옛 이름(유형화·리포트·미션…)이고 "내 영상"·영상 작업 공간이 없다. 영상 탭의 도움말은 탭이 품은 화면(기획안·콘티·진단)의 것을 쓴다.
12. **자막 도구 설치**: 설치 API가 없어 콘티 화면의 `ytc captions setup` 안내가 남아 있다.
13. **폴더 열기**: 촬영 영상 영역은 사용자의 촬영 폴더 경로와 클립 출력 폴더를 보여 준다("폴더 열기" API 없음, Phase 3에서 다시 본다).
