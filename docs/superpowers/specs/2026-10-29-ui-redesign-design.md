# yt-coach UI 개선 — 설계

출처: 사용자 지시서(2026-10-29, 아래 1~6절 원문 그대로)와 Claude Design 캔버스 "yt-coach UI 개선 시안"(https://claude.ai/artifact/DSSo87bVsV4ktzdCk6h1bE). 시안 4장의 원본(.dc.html)은 `docs/ui-mockups/`에 있다(정적 마크업과 예시 데이터 — 구현의 배치·크기·색 기준). 7절은 구현하며 정한 것(내 판단).

## 0. 작업 규칙
- **먼저 현재 프론트엔드 구조를 파악한다**(프레임워크, 라우터, 컴포넌트·스타일 위치, API 호출부). 파악 결과를 3~5줄로 보고한 뒤 Phase 1을 시작한다. (보고 완료, 7절 참고)
- **백엔드 API·데이터 스키마·md 파일 포맷은 바꾸지 않는다.** UI가 필요로 하는 값이 API에 없으면 구현하지 말고 목록으로 보고한다.
- 기존 라우트 URL은 리다이렉트로 유지한다(북마크·링크 보존).
- Phase 단위로 커밋하고, 각 Phase 끝에 데스크톱(1280px)과 폰(390px) 폭에서 화면을 확인한다.
- 문구는 한국어, 초보 크리에이터 기준의 쉬운 말.

## 1. 핵심 원칙
1. **영상(프로젝트) 한 편 중심.** 기획안·콘티·촬영·진단은 영상 페이지 안의 탭이다. 메뉴를 옮겨 다니지 않는다.
2. **단순하게.** 한 화면에 주요 행동 버튼은 1개. 보조 행동은 작은 버튼이나 텍스트 링크. 큰 배너·과한 여백 금지.
3. **고르는 화면은 훑기 좋게.** 카드에는 제목·한 줄·태그·근거 썸네일만. 상세는 옆 패널(데스크톱) 또는 바텀시트(폰).
4. **기계 용어 숨기기.** 로컬 경로, 파일명(`*.md`, `*-conti.html`), 터미널 커맨드 안내를 화면에서 없앤다. 영상 제목·날짜로 표시한다.
5. **Claude 작업 상태는 헤더 한곳.** "Claude가 ○○ 만드는 중 · 18초" 상태 칩. 끝나면 토스트로 알리고 결과로 이동 링크.
6. **폰 우선 고려.** 390px에서 깨지지 않을 것. 촬영 현장에서 쓰는 촬영 모드가 있다.

## 2. 정보 구조 (메뉴)
| 그룹 | 항목 | 기존 라우트 |
|---|---|---|
| 영감 | 레퍼런스 (개수), 유형 (개수), 모티브 (개수) | `#/refs`, `#/library`는 레퍼런스 안 탭, `#/typify`, `#/motif` |
| 내 영상 | 진행 중 영상 목록(제목 + 진행 막대 + 현재 단계), `+ 새 영상 시작` | `#/draft`, `#/conti`, `#/diagnose` → 영상 작업 공간으로 통합 |
| 성장 | 오늘 미션, 주간 리포트 | `#/mission`, `#/report` |

- 새 라우트: `#/video/:id` (탭: `plan` 기획안 / `conti` 콘티 / `shoot` 촬영 체크 / `diagnose` 진단), `#/video/:id/shoot` (촬영 모드)
- 영상 id는 draft 파일 slug를 그대로 쓴다(새 저장 구조 만들지 않음).
- 데스크톱: 왼쪽 사이드바(220~260px, 흰 배경 계열, 검은 사이드바 폐지). 폰: 하단 탭 4개(홈 / 영감 / 내 영상 / 미션).
- 헤더: 로고, 카테고리 선택, Claude 작업 상태 칩, 도움말(작은 버튼). **로컬 경로 표시 제거.** "서버 끄기"는 도움말 메뉴 안으로.

## 4. 화면별 명세

### 4.1 홈 `#/home`
- 데스크톱: 다음 할 일(한 줄 카드 + 작은 주요 버튼) → 만들고 있는 영상(최대 3, 더보기) → 오늘 미션 → 최근 결과물(파일명 대신 "영상 제목 · 콘티 · 10월 29일").
- 폰: 다음 할 일 카드(어두운 카드, "촬영 모드 시작" 큰 버튼) → 오늘 미션 → 만들고 있는 영상 3개(썸네일 + 6칸 단계 점 + 현재 단계).

### 4.2 영상 작업 공간 `#/video/:id` (시안: 데스크톱 · 영상 작업 공간)
위에서 아래로:
1. 브레드크럼 `내 영상 › 짧은 제목`
2. 제목(30px, 굵게, 왼쪽 빨간 세로선) + 메타 줄: 시작일 · 목표 길이 · 출처 모티브 칩 · 유형 칩
3. **진행 바 한 줄**(흰 카드): 6단계 막대(기획안 / 다듬기 / 콘티 / 촬영 / 편집 / 진단, 라벨에 ✓ – ●) + 오른쪽에 `촬영 0 / 6컷`, `폰 촬영 모드`(빨강 작은 버튼), `다 찍음`(테두리 작은 버튼). 현재 단계에 따라 오른쪽 행동이 바뀐다.
4. 탭 줄(밑줄 탭) + 오른쪽에 요약(`6컷 · 15:00 · 평균 컷 3.0초`)과 텍스트 링크 `인쇄`, `다시 만들기`
5. (콘티 탭) 도구 줄: 컷 검색(작게), 구간 필터 칩(전체 / 도입 / 본론 / 마무리), 오른쪽 보기 전환(카드 / 리스트)
6. (콘티 탭) 컷 카드 그리드 `repeat(auto-fill, minmax(210px, 1fr))`, 카드: 프레임 영역 112px(레퍼런스 프레임 이미지가 있으면 표시, 없으면 샷 설명 텍스트) + 좌상단 `01 · 0:00–0:10` + 섹션 태그 + 행동(굵게) + 대사(따옴표) + `참고 · 근거 모티브/영상`
- 기획안 탭: 기존 기획안 md 렌더링 + 편집. 진단 탭: 기존 진단 화면을 이 영상 기준으로.
- 기존 "스토리보드 HTML" 버튼 기능은 `인쇄`로 연결.

### 4.3 모티브 `#/motif` (시안: 데스크톱 · 모티브 고르기)
- 상단: 제목 + 한 줄 설명, 오른쪽에 주제 입력 + `새 카드 뽑기 · 약 30초`(클릭 시 헤더 상태 칩으로 진행 표시, 화면은 계속 사용 가능)
- 필터 칩: 전체 / ★ / 흐름 / 기법 / 각도 / 조합 (개수 포함)
- 카드 그리드 `minmax(230px, 1fr)`: 종류 태그, ☆/★ 토글, 제목, **한 줄 요약**, 근거 영상 썸네일 3개 + `근거 영상 N`. 본문 전문·단계 목록은 카드에 넣지 않는다.
- 카드 클릭 → 오른쪽 상세 패널(데스크톱, 380px) / 바텀시트(폰): 설명, "이렇게 찍어 보세요" 단계, 근거 영상(썸네일 + 제목 링크), 이 카드로 만든 영상, 주요 버튼 `이 카드로 새 영상 시작`
- "한 줄 요약" 필드가 데이터에 없으면 본문 첫 문장을 잘라 쓰고, 별도 필드가 필요하면 보고만 한다.
- "터미널 /yt-coach:yt-inspire에서…" 안내 문구 제거.

### 4.4 촬영 모드 `#/video/:id/shoot` (시안: 폰 · 촬영 모드) — 폰 전용 우선
- 어두운 전체 화면. 상단: 닫기(44px), "촬영 모드 / 짧은 제목", 오른쪽 `3 / 6`
- 컷 진행 막대(완료 초록, 현재 흰색, 남은 것 회색)
- 프레임 영역(216px): 섹션 태그, 타임코드, 샷 설명, 찍은 컷은 `찍음 ✓` 배지
- 행동(22px 굵게), 대사 박스(18px), 촬영 팁 2개
- 하단: `‹` / 큰 `찍었어요 ✓`(찍은 뒤엔 `다음 컷으로`, 마지막엔 `전부 찍었어요!`) / `›`
- 체크 상태는 서버에 저장(기존 "촬영함 체크" API 재사용). API가 컷 단위를 지원하지 않으면 우선 브라우저 저장(try/catch)으로 하고 보고한다.
- 화면 꺼짐 방지(Wake Lock API, 지원 시)

### 4.5 레퍼런스·유형·리포트·미션
- 레퍼런스: 기존 썸네일 그리드 유지. 헤더 톤·버튼 크기·칩 스타일만 토큰에 맞춘다. 공용 라이브러리는 탭으로.
- 유형: 축별 판정 표와 아키타입 카드 유지, 토큰 적용.
- 미션·리포트: 토큰 적용, 파일명 노출 제거.

## 5. 진행 순서
| Phase | 내용 | 완료 조건 |
|---|---|---|
| 1 | 토큰·공통 컴포넌트(버튼 S/M, 칩, 카드, 탭, 상태 칩), 새 헤더·사이드바·폰 하단 탭, 경로/파일명 노출 제거 | 모든 화면이 새 셸로 뜨고 390px에서 가로 스크롤 없음 |
| 2 | 영상 작업 공간 `#/video/:id` + 탭 통합, 기존 라우트 리다이렉트 | 홈의 진행 중 영상 클릭 → 작업 공간, 기획안·콘티·진단 탭 전환 |
| 3 | 콘티 카드 그리드 + 도구 줄 | 기존 콘티 데이터로 컷 카드가 모두 보임 |
| 4 | 모티브 카드 + 상세 패널/바텀시트, "새 영상 시작" 연결 | 카드 선택 → 상세 → 새 영상 생성 흐름 동작 |
| 5 | 촬영 모드 | 폰 폭에서 컷 넘기기·체크·저장 동작 |
| 6 | 홈 재구성, Claude 작업 상태 칩·토스트 | 장시간 작업 중 다른 화면 이동 가능, 완료 알림 |
| 7 | 나머지 화면 토큰 적용, 정리 | 전 화면 시각 점검 |

## 6. 하지 않을 것
- 백엔드·스키마·md 포맷 변경, 새 저장소 도입
- 새 UI 라이브러리 대량 도입(필요하면 먼저 제안)
- 이모지 아이콘(★☆ 별표 제외), 그라데이션 장식

## 7. 구현 결정 (내 판단)

현재 구조(0절 보고): 프레임워크 없는 ES 모듈, `dom.js`의 `h()`로 DOM 생성, 해시 라우터·메뉴는 `scripts/ui/static/app.js`, 화면은 `pages/*.js` 15개(콘티 편집기 `pages/conti.js` 2,405줄), 스타일은 `app.css` 한 파일(shadcn zinc 토큰, 검은 사이드바), 서버 호출은 `api.js`의 `api()`, 긴 Claude 작업은 `/api/jobs/current?kind=` 폴링.

- **폰트**: 외부 URL 금지 규칙(정적 파일에 `https?://` 금지 테스트, 로컬 전용) 때문에 Google Fonts를 불러오지 않는다. `font-family: 'Noto Sans KR', 'Malgun Gothic', 'Apple SD Gothic Neo', system-ui, sans-serif`(설치돼 있으면 Noto), 타임코드 `'JetBrains Mono', ui-monospace, Consolas, monospace`. 폰트 파일을 저장소에 넣지 않는다(라이브러리 대량 도입 금지와 같은 취지).
- **토큰**: 3절 값을 `app.css`의 기존 토큰 자리에 넣는다(기존 이름을 쓰는 곳이 많으므로 기존 이름은 새 값으로 다시 가리키고, 3절 이름을 추가). 색 대비 4.5:1을 지킨다(시안 값 그대로면 통과).
- **다크 모드**: 지시서대로 촬영 모드만 어두운 배경. 지금 있는 앱 전체 다크 테마(`prefers-color-scheme`)는 이번에 끈다(라이트 고정). (지시서 "다크 모드: 촬영 모드만" 해석)
- **영상 id**: draft 파일 이름에서 `.md`를 뗀 것(`drafts/` 아래 상대 경로, 하위 폴더면 `/`를 포함한 채 인코딩). 서버는 지금처럼 `path`로 받는다.
- **6단계 진행**: 기존 API로 계산한다 — 기획안(draft 있음) / 다듬기(polish 결과가 있는지 기존 API로 확인, 없으면 "–" 건너뜀) / 콘티(conti 있음) / 촬영(draft `filmed_at`) / 편집(편집본 경로 또는 내 영상 진단 대상이 있으면) / 진단(이 영상에 진단 결과). API로 알 수 없는 단계는 "–"로 두고 보고 목록에 적는다.
- **컷별 촬영 체크**: 서버에 컷 단위 체크 API가 없다(`/api/drafts/filmed`는 기획안 단위). 브라우저 저장(`localStorage`, 키 `ytc.shoot.<영상 id>`, try/catch)으로 하고, `전부 찍었어요!`를 누르면 기존 `/api/drafts/filmed`로 기획안 단위 "다 찍음"을 저장한다. 보고 목록 1번.
- **모티브 한 줄 요약**: 별도 필드가 없으면 본문 첫 문장(최대 60자). 보고 목록 2번.
- **Claude 작업 상태 칩**: 기존 `/api/jobs/current?kind=` 폴링을 헤더 한곳에 모은다(모든 kind). 서버에 "모든 작업" 조회가 없으면 kind별로 묻는다(새 API 금지).
- **장면 단위 콘티와의 관계**: 별도 브랜치(`feat/scene-conti`)에서 콘티의 서버 쪽(장면 합치기, 사진 설명, 장면별 사진 고르기)을 만들고 있다. 그 작업의 화면 부분은 이 개편의 Phase 3(콘티 카드 그리드)에 합친다: 카드 프레임 영역에 장면 사진, `참고 · <설명>` / `구도만 참고 · <설명>`, 합치기·사진 설명 만들기·사진 다시 고르기 버튼. Phase 3은 `feat/scene-conti`가 이 브랜치에 합쳐진 뒤에 시작한다. 이것은 지시서의 "백엔드 변경 금지"에 해당하지 않는다(사용자가 따로 승인한 작업).
- **콘티 편집 기능 보존**: 지금 콘티 편집기의 기능(대사·가이드 고치기, 대안, 컷 넣기/빼기/옮기기, 길이, 이력, 촬영 영상 영역, SRT·자막 영상)은 모두 콘티 탭 안에 남긴다. 카드 그리드는 보는 방식이고, 카드를 누르면 지금의 편집 패널이 열린다.
- **보고 목록**(구현하지 않고 사용자에게 알릴 것): 컷별 촬영 체크 API, 모티브 한 줄 요약 필드, 6단계 중 API로 알 수 없는 단계, 근거 영상 썸네일이 모티브 API에 없으면 그것.
- **촬영 체크 탭 키**: 영상 작업 공간의 탭 키는 `plan` / `conti` / `check`(촬영 체크) / `diagnose`. `#/video/:id/shoot`은 폰 촬영 모드 라우트라 탭 키로 쓰지 않는다(2절 `shoot` 탭 표기는 `check`로 읽는다). 탭 없이 `#/video/:id`로 열면 촬영을 마친 영상은 진단, 나머지는 콘티 탭.
- **떠나기 전 확인**: 콘티 컷 편집·다듬기 입력처럼 저장하지 않은 입력이 있으면 탭 이동·다른 화면 이동·카테고리 바꾸기 전에 화면 안에서 묻는다(`버리고 이동` / `계속 편집`, 브라우저 대화상자 없음). 머무르면 주소와 카테고리는 영상 그대로 돌아온다.

- **촬영 모드(Phase 5)**: `#/video/:id/shoot`은 영상 페이지가 아니라 따로 화면(`pages/shoot.js`)이고, 이 주소에서만 헤더·사이드바·하위 링크·하단 탭을 숨기고 어두운 토큰을 쓴다(`body.shoot-mode.shoot-dark`, 다른 화면으로 가면 원래대로). 폰 기준 한 열(최대 480px), 데스크톱에선 가운데. 시안의 `컷`은 앱 표기에 맞춰 `장면`(`다음 장면으로`, `이전/다음 장면`). 프레임은 장면 사진이 있으면 사진 위에 구간 태그·타임코드·샷·`찍음 ✓`를, 없거나 못 읽으면 어두운 칸에 샷 설명. 팁은 장면 `guide`를 문장으로 나눠 최대 2개. 열면 아직 안 찍은 첫 장면부터, `다음 장면으로`는 다음 안 찍은 장면으로(끝이면 처음의 남은 장면). 찍은 장면은 `찍음 지우기`(작은 링크)로 되돌린다. ←/→는 이 화면에서만(입력 중·수정키 제외), 화면 꺼짐 방지는 Wake Lock(지원 시, 실패 무시, 떠나거나 다 찍으면 해제, 탭이 다시 보이면 다시 요청). `전부 찍었어요!` → `/api/drafts/filmed {filmed: true}`(기획안이 바뀌었으면 새 hash로 한 번 더) → 끝 화면과 `영상으로 돌아가기`. 콘티가 없으면 `콘티 탭으로 가기`, 없는 영상이면 `내 영상으로 가기`. 촬영 체크 탭: `촬영 N / M장면` · `폰 촬영 모드` · `다 찍음` · `남은 장면 N개` · 장면 목록(체크박스, 촬영 모드와 같은 저장). 빨간 버튼은 화면에 하나: 촬영이 다음 단계면 탭 머리의 `폰 촬영 모드`가 빨강이고 진행 카드는 이 탭에서 촬영 숫자·버튼을 되풀이하지 않는다, 촬영을 마친 뒤엔 진행 카드의 다음 행동(`진단하기`)만 빨강. (수정 1차) 진행 막대는 최대 40칸(장면이 많으면 칸 하나가 여러 장면, 전부 찍은 칸만 초록, 지금 장면이 든 칸은 흰색, 그 칸을 다 찍었으면 초록에 흰 테두리). 콘티에 반복 컷이 남아 있으면 촬영 모드와 촬영 체크 탭에 한 줄 "같은 장면이 여러 컷으로 나뉘어 있어요. 콘티 탭에서 장면으로 합치면 찍기 편해요." 촬영 체크 탭은 `전체 / 남은 장면` 칩으로 거른다(남은 장면 보기에서 체크한 줄은 칩을 다시 누를 때까지 남는다). 다 찍음인데 이 브라우저에 체크가 없으면 "이 영상은 촬영 완료로 표시돼 있어요. 다시 찍을 장면만 체크하세요."
- **콘티 카드 보드(Phase 3)**: 콘티 탭은 위에서부터 `이력`·메타 줄 → 장면 도구 줄(`장면으로 합치기`는 반복 컷이 있을 때만, `사진 설명 만들기`는 설명 없는 레퍼런스 사진이 있을 때 안내 한 줄과 함께, `사진 다시 고르기`는 설명 있는 사진이 있을 때; 반복이 남아 있으면 끄고 "반복 컷을 먼저 장면으로 합쳐 주세요") → 촬영 영상(접힘) → 도구 줄(장면 검색 · 전체/도입/본론/마무리 칩 · 카드/리스트) → 보드 → `자막 내보내기`(SRT·편집본 맞추기·움직이는 자막 영상, 접힘). 구간: 도입 = hook+intro, 마무리 = cta+outro, 나머지 본론. 보기 전환은 `localStorage` `ytc.conti.view`(try/catch). 카드를 누르면 지금의 편집 패널이 오른쪽(900px 이하는 보드 위)에 열리고 `닫기`로 카드로 돌아간다. 카드 ⋯ 메뉴는 리스트와 같은 넣기·복제·삭제에 `앞으로/뒤로 옮기기`를 더한다(카드엔 끌기가 없다). 검색·구간 필터 중인 리스트는 넣기 칸과 끌기를 숨긴다. 사진이 주 그림이고 도식은 사진이 없을 때만(카드·리스트·패널·인쇄용 HTML). 요약 줄은 `장면 N개 · 15:00 · 평균 X초`(장면 단위 기획은 편집 컷 평균이 없다). 장시간 작업(합치기·사진 설명·사진 고르기)은 Phase 6 전까지 도구 줄 아래 한 줄 진행(`data-job-kind`).

- **홈·상태 칩(Phase 6)**: 홈은 데스크톱 `다음 할 일`(한 줄 + 작은 주요 버튼, 촬영 차례면 그 영상의 `촬영 체크 열기`) → `만들고 있는 영상`(3개 + `N개 더 보기`, 줄마다 6단계 점과 촬영함 체크) → `오늘 미션` → `최근 결과물`("영상 제목 · 콘티 · 10월 29일", 누르면 그 영상의 기획안·콘티 탭이나 리포트). 폰(640px 이하)은 어두운 `다음 할 일` 카드(촬영이 다음이면 `N / M장면` 막대와 빨간 `촬영 모드 시작`, 아니면 그 단계의 행동: `콘티 만들기`·`진단하기`·카테고리 단계·`새 영상 시작`) → `오늘 미션` → 만드는 중인 영상 3개(첫 장면 사진, 6칸 단계 막대, `촬영 차례` 같은 단계 말) + `전체 N편`. 너비가 바뀌면 받은 자료로 다시 그린다(새 요청 없음). 지금까지 홈에 있던 카테고리 단계 줄과 `다른 카테고리` 목록은 뺐다(4.1의 네 칸만, 카테고리는 머리말에서 바꾼다). `새 영상 시작`은 어디서나 `#/motif`. 머리말 상태 칩은 작업 kind 18개(`help_chat` 제외: 도움말 패널이 직접 보여 준다)를 `/api/jobs/current?kind=`로 묻는다: 모든 kind는 15초마다, 도는 작업(또는 확인을 기다리면서 아직 일하는 항목이 있는 작업)이 있는 kind만 1.5초마다, 탭이 숨으면 멈춘다. 사용자 확인만 기다리는 작업(수집 저장 확인)은 15초 순회로 충분하다. 모든 요청이 실패한 순회가 3번 이어지면(서버가 꺼짐) 기억한 작업을 지우고 15초 간격으로 돌아가며, `bad_token`(서버가 새로 켜짐)이면 묻기를 멈춘다. 화면이 작업을 시작하거나 폴링한 응답(`job`이 든 모든 `api()` 응답)은 `ytc:job` 이벤트로 칩에 바로 들어간다(`ctx.jobStarted(kind)`도 있다). 하나면 `Claude가 ○○ 만드는 중 · 18초`(Claude를 부르지 않는 컷 파일·자막 맞추기·자막 영상은 `○○ 하는 중`; 촬영 영상 처리는 장면 맞추기에 Claude를 불러 `Claude가 촬영 영상을 맞추는 중`), 확인을 기다리면 `○○ · 확인할 게 있어요`, 둘 이상이면 `작업 N개`(누르면 목록: 문구 · 경과 · `보기` 링크). 폰은 `작업 중 · 18초`. 칩이 돌던 것을 본 작업이 끝나면 토스트(`○○ 끝났어요` / `… 확인할 게 있어요` / `못 끝냈어요: 이유` / `멈췄어요`)와 `결과 보기`(콘티 계열 → 그 영상 콘티 탭, 다듬기 → 기획안 탭, 진단 → 진단 탭, 사진 설명 → 시작한 콘티 탭 또는 `#/refs`, 모티브 → `#/motif`, 수집 → `#/refs`(확인 대기면 `#/add`) 등). 그 결과 화면을 보고 있으면(수집은 `#/add`와 `#/refs`를 같은 화면으로 본다) 토스트를 띄우지 않는다(화면이 직접 결과와 알림을 보여 준다). 칩 옆의 보이지 않는 알림 줄(`aria-live=polite`, 다시 그리는 칩 밖)이 작업이 시작될 때와, 토스트 없이 끝날 때(결과 화면에 있을 때) 한 번 읽어 준다(경과 초는 읽지 않는다). 끝난 작업은 60초 동안 칩 목록에 `○○ · 끝남` + `결과 보기` 줄로 남는다(진행 중인 것이 없으면 칩은 `끝난 작업 N개`) — 토스트가 사라진 뒤에도 키보드로 결과에 갈 수 있게. 모티브 화면의 진행 줄은 칩이 맡고(버튼은 `카드 뽑는 중…`), 콘티 장면 도구 줄(합치기 시간 안내, 사진 설명 장 수·멈추기, 사진 고르기 묶음)과 각 화면 작업 상자의 단계 문구(기획안·다듬기·진단·미션·회고·유형화·라이브러리)는 그 화면의 상세라 남겼다.

- **나머지 화면(Phase 7)**: 레퍼런스·공용 라이브러리·유형·리포트·미션·가이드·올린 영상 진단은 배치를 그대로 두고 토큰만 맞췄다. 공용 라이브러리는 레퍼런스 화면 위쪽 밑줄 탭(`레퍼런스 / 공용 라이브러리`, `#/add`에서도 보임)이고, 그 안의 기법 / 기획안 틀 / 공유하기는 탭 속 탭이 되지 않게 칩(`ui-chip`)으로 둔다. 거르기·고르기 버튼(레퍼런스 구분 필터, 리포트 날짜, 라디오 선택)은 칩 모양, 화면 안 탭(리포트·가이드)은 `ui-tab`과 같은 밑줄(빨강, 굵게). 섹션 코드(`hook`, `body/story`)는 화면에서 이름(`훅`, `본문(이야기)`)으로: 레퍼런스 장면 프레임 설명, 유형 골격·비율, 진단 골격, 그리고 서버·Claude가 쓴 글 안의 코드(유형 판정 근거, 아키타입 이름; `labels.js` `humanizeLabels`, 화면 표시만, 저장 글과 편집 칸은 그대로). 유형 아키타입 카드는 구성 영상 5개까지 보이고 나머지는 `N개 더 보기`. 칩 크기는 하나(`ui-chip`·라디오 선택·라이브러리 칩 모두 32px, 13px). 콘티 이력 종류 `md 직접 수정`은 `파일 직접 수정`. 화면 이름은 메뉴와 맞춘다: `유형화` 화면 → `유형`(하는 일 이름 "유형화 실행"은 그대로), `ref N개` → `레퍼런스 N개`. 공용 라이브러리 정보 줄은 저장소 주소 대신 저장소 이름만(`library-utils.js` `repoName`). 미션 제출 칸 이름은 `첨부할 사진·스크린샷·글 파일 위치(선택)`(업로드 API가 생기기 전까지, 보고 16번). 올린 영상 진단의 돌아가기는 `← 내 영상`(`#/videos`, 옛 `#/diagnose` 목록은 거기로 넘어간다). 미션·리포트 h1은 `미션`·`리포트`로 두고 브라우저 탭 이름은 사이드바와 같은 `오늘 미션`·`주간 리포트`로 했고 리포트 날짜 버튼의 진한 채움을 칩으로 바꿔 주요 버튼(`리포트 만들기`)을 하나로 했다. 도움말 챗봇 메뉴(`api_help.MENU`, 문구만)와 `app.js` SCREENS는 사이드바 순서로: 홈 · 레퍼런스 · 공용 라이브러리 · 유형 · 모티브 · 내 영상 · 기획안 · 콘티 · 진단 · 오늘 미션 · 주간 리포트 · 가이드(기획안·콘티·진단은 옛 주소 → 내 영상/영상 탭). 도움말 문서는 새 위치(영감/내 영상/성장, 영상 탭, 촬영 체크·촬영 모드, 작업 상태 칩)로 고쳤고, 화면에 그대로 보이는 가이드 문서에서 파일 이름(`index.md`, `mine/`)을 뺐다. 도움말 문서에는 파일 이름·폴더 경로·터미널 명령을 쓰지 않는다(설치는 "Claude에게 '…설치해줘'라고 말하세요", 지운 파일은 "휴지통 폴더(작업 폴더 안)"; `test_help_pages_hide_file_names_paths_and_commands`). 가이드의 단계 링크는 완료 배지 때문에 옛 주소(`#/draft` 등)를 쓰고 글로 위치를 적는다.

Phase 1–7에서 확인한, 지금 API로는 얻을 수 없어 구현하지 않았거나 화면이 대신 계산하는 값이다(백엔드 변경 금지). `docs/ui-mockups/REPORT.md` 대신 이 목록을 쓴다. 항목마다 **필요한 것 → 지금 화면 → 고칠 API** 순서다. 같은 원인은 한 항목으로 묶었다.

#### A. 촬영·진행 단계
1. **장면별 촬영 체크** (Phase 5)
   - 필요: 장면 하나하나의 "찍음"을 기기 사이에 나누어 저장.
   - 지금: 브라우저 저장(`localStorage` `ytc.shoot.<영상 id>`, 장면 id 목록). 다른 브라우저·폰과 공유되지 않고, 저장이 막힌 창(시크릿 등)에서는 탭을 닫으면 사라진다(화면이 한 줄로 알린다). `촬영 N / M장면`은 이 체크를 세고, 기획안이 `다 찍음`이면 전부로 센다. `전부 찍었어요!`만 서버(`filmed_at`)에 남는다. 장면을 지우거나 합치면 콘티에 없는 id의 체크는 세지 않는다(합친 장면은 첫 컷 id를 이어 쓴다).
   - API: `POST /api/conti/shot {path, cut_id, filmed}`(콘티 프런트매터나 별도 기록에 장면 id 목록)와 `/api/conti` 응답에 장면별 `filmed`.
2. **"편집" 단계** (Phase 1)
   - 필요: 편집본이 있는지.
   - 지금: 편집본 API가 없어 자막 영상(`captions`)이 있으면 완료로 본다.
   - API: `/api/status` 영상 `steps`에 편집본(사용자가 넣은 편집본 경로나 내 영상 진단 대상 연결) 단계.
3. **알 수 없는 단계** (Phase 2)
   - 필요: 6단계 전부의 상태.
   - 지금: `/api/status`를 못 받으면 촬영·편집·진단은 `–`, 진행 카드의 오른쪽 행동은 비운다(완료로 표시하지 않음).
   - API: 영상 한 편 읽기(9번)가 단계를 함께 주면 사라진다.
4. **홈 영상 사진·장면 수, 오늘 미션 제목** (Phase 6)
   - 필요: 홈 카드의 첫 장면 사진, `N / M장면`, 오늘 미션 제목·분량.
   - 지금: 폰 홈이 다음 영상과 목록 3개의 콘티(`/api/conti`, 최대 4번)와 `/api/mission`을 더 읽는다(사진이 없으면 회색 칸, 미션 실패면 상태만).
   - API: `/api/status` 영상에 `thumb`(첫 장면 사진)·`scenes`(장면 수), 카테고리에 오늘 미션 `title`·`minutes`.

#### B. 영상·모티브 데이터
5. **짧은 제목** (Phase 2)
   - 필요: 브레드크럼·촬영 모드용 짧은 제목.
   - 지금: 제목을 24자에서 자른다.
   - API: 기획안 프런트매터 `short_title`(draft 스킬이 쓰고 `/api/draft`가 낸다).
6. **모티브 칩** (Phase 2)
   - 필요: 영상의 출처 모티브 카드 이름.
   - 지금: 기획안 `source`가 카드 id이고 `/api/motif`가 그 카드를 아직 가질 때만 나온다. 아키타입 출처("A1")면 유형 칩만.
   - API: `/api/draft`가 출처 카드의 제목·종류를 함께 준다(카드가 지워졌으면 저장 당시 제목).
7. **모티브 한 줄 요약** (Phase 4)
   - 필요: 카드 격자의 한 줄 요약.
   - 지금: 카드의 `idea` 첫 문장을 60자에서 잘라 쓴다(`motif-utils.js` `oneLine`). 첫 문장이 근거 설명이면 요약답지 않을 수 있다.
   - API: 카드 필드 `summary`(yt-inspire 스킬이 쓴다). 스킬만 고치는 대안: `idea` 첫 문장을 "내 영상에서 할 것" 한 줄로 쓰게 한다.
8. **근거 영상 썸네일과 "이 카드로 만든 영상"** (Phase 4)
   - 필요: 카드의 근거 영상 사진, 카드로 만든 영상 목록.
   - 지금: 근거(`evidence`)는 id·제목뿐이라 `/api/refs?category=`를 한 번 더 읽어 id로 맞춘다(목록에 없는 영상은 회색 칸). 만든 영상은 `/api/draft/list?category=`에서 `source`가 카드 id인 기획안을 고른다(다른 카테고리 기획안은 안 보인다).
   - API: `/api/motif` 카드에 `evidence[].thumb`, `drafts[]`(id·제목·카테고리).
9. **최근 결과물 제목** (Phase 1)
   - 필요: "영상 제목 · 콘티 · 10월 29일".
   - 지금: `/api/status.recent`는 파일 경로만 줘서 같은 응답의 영상 제목으로 채우고, 다른 카테고리 기획안은 파일 이름에서 날짜·확장자·대시를 뺀다.
   - API: `recent[]`에 `title`·`kind`·`video_id`.

#### C. 읽기 횟수
10. **개수만 주는 API 없음** (Phase 1)
    - 필요: 사이드바 숫자(레퍼런스·유형·모티브).
    - 지금: 화면을 옮길 때마다 `/api/status`·`/api/typify`·`/api/motif`(카드 전체)를 읽는다.
    - API: `/api/status` 카테고리에 `archetypes`·`motifs` 개수.
11. **영상 한 편 읽기** (Phase 2)
    - 필요: 작업 공간 머리(제목·메타·단계·장면 수).
    - 지금: 처음 열 때 `/api/draft`·`/api/status`·`/api/motif`·`/api/typify`·`/api/conti`를 읽는다(탭 이동은 `/api/status`만, 촬영 체크 탭과 콘티 탭을 떠날 때 `/api/conti`도).
    - API: `GET /api/video?path=`(기획안 요약 + 단계 + 출처 이름 + 장면 수 한 번에).
12. **모든 작업 조회** (Phase 6)
    - 필요: 머리말 상태 칩이 도는 작업 전부.
    - 지금: kind 18개를 `/api/jobs/current?kind=`로 따로 묻는다. 놀 때 15초마다 18번(초당 1.2번), 도는 kind는 1.5초마다(실측: 놀 때 16초에 18번, 하나 돌 때 9초에 23번), 탭이 숨으면 0번. 같은 kind가 여럿 도는 콘티는 `current`가 가장 최근 것만 줘서 이전 작업은 `/api/jobs/<id>`로 따로 묻는다.
    - API: `GET /api/jobs/active`(도는 작업과 확인 대기 작업 전부).

#### D. 작업 진행 시간
13. **작업 경과·남은 시간** (Phase 3, 6)
    - 필요: 상태 칩의 `· 18초`, 모티브 "약 30초" 중 지난 시간, 사진 설명 "약 M분", 사진 고르기·합치기 진행률.
    - 지금: 경과는 칩이 그 작업을 처음 본 때부터 센다(작업 중 화면을 새로 열면 0초부터). 사진 설명 남은 시간은 화면이 8장 한 묶음 45초(`scripts/timings.py` 가정값)로 센다(실측이 쌓여도 따라가지 않는다). `conti_refs`·`conti_merge`는 단계 문구(`1/3 묶음`)와 회전 표시만.
    - API: 작업 스냅숏에 `started_at`, 항목에 `progress`(0–1)와 `eta_sec`(서버의 실측 시간 기준).

#### E. 설치·파일·폴더 (화면에 남은 기계 말)
14. **자막 도구·받아쓰기 설치** (Phase 1, 3)
    - 필요: 설치 안내 없이 설치.
    - 지금: 콘티 탭에 `ytc captions setup`, 촬영 영상 영역에 `pip install faster-whisper` 안내가 남아 있다(정적 검사 허용 목록).
    - API: `POST /api/setup/captions`·`/api/setup/stt`(설치 작업)와 설치 상태 조회.
15. **촬영 폴더와 클립 폴더** (Phase 1, 3)
    - 필요: 폴더 경로를 보이지 않고 열기.
    - 지금: 촬영 영상 영역이 사용자가 넣은 촬영 폴더 경로와 클립 출력 위치를 보여 준다.
    - API: `POST /api/open-folder {kind, path}`(탐색기로 열기)와 폴더 별칭.
16. **미션 제출 파일** (Phase 7)
    - 필요: 사진·스크린샷을 골라 내기.
    - 지금: 업로드 API가 없어 미션 완료 제출 칸에 사용자가 파일 경로를 적는다(칸 이름은 `첨부할 사진·스크린샷·글 파일 위치(선택)`). 피드백에는 낸 파일 이름이 보인다.
    - API: `POST /api/mission/upload`(브라우저 파일 선택 → 서버가 잠깐 복사).
17. **공용 라이브러리 저장소 주소** (Phase 7)
    - 필요: 연결한 저장소를 알아볼 이름.
    - 지금: `/api/library/status`의 `remote`는 GitHub 주소 전체(로컬 폴더면 서버가 `(로컬) 이름`으로 가린다)라, 화면이 마지막 이름(`friends-lib`, `(로컬) t7lib`)만 떼어 보인다.
    - API: status에 `name`(저장소 이름).

#### F. 서버가 만드는 글
18. **카테고리 리포트 HTML** (Phase 7) — **우선순위 높음**: 이번 개편 뒤 화면에 기계 말이 가장 많이 남은 곳이다(주간 리포트 탭을 열면 바로 보인다).
    - 필요: 화면과 같은 쉬운 말.
    - 지금: 리포트 탭은 스크립트가 만든 HTML(`/files/reports/…html`)을 샌드박스 프레임에 그대로 보여 준다. 그 안에 다음이 영어 코드로 나온다: 축 이름(`structure`, `hook`, `narrative`, `title`, `pacing`, `shots`), 섹션 코드와 범례(`hook`, `intro`, `body`, `body/story`, `transition`, `cta`, `outro`), 머리 줄의 `ref N개 · mine N개`. 프레임 안이라 화면(`labels.js`)이 바꿀 수 없다.
    - API(스크립트): 리포트를 만드는 스크립트가 `labels.js`와 같은 한국어 이름표(축: 구조·훅·서사·제목·컷 속도·샷, 섹션: 훅·인트로·본문(이야기)…, `레퍼런스`·`내 영상`)로 쓴다. 백엔드 변경이라 이번 범위 밖.
19. **진단 갭 이름과 오류 문구** (Phase 7)
    - 필요: 갭·오류를 쉬운 말로.
    - 지금: 갭 제목과 서버 오류 문구(`message`)는 서버 글 그대로 보인다(일부는 "터미널에 나온 새 주소로 여세요" 같은 기계 말).
    - API: 오류 `message`를 화면용 문장으로 다듬는다(코드 `error`는 그대로).
20. **도움말 챗봇 메뉴** (Phase 1 보고 → Phase 7 고침)
    - `api_help.MENU`(문구만)를 새 이름·순서(유형, 내 영상, 기획안·콘티·진단은 영상 탭)로 바꾸고 `_chatbot.md`에 화면 구조를 적었다. 남은 공백: 메뉴에 영상 한 편(`#/video/<id>`) 주소가 없어 챗봇은 "내 영상에서 영상을 고른 뒤 ○○ 탭"으로 안내한다(`situation`에 영상 id가 없다).
