# 홈: 다음 할 일과 영상별 진행 — 설계

2026-10-25. 사용자 요청: "홈 화면 디자인 개선 — 지금 어디까지 했고 다음에 뭘 해야 하는지", 범위는 "둘 다"(카테고리 전체 + 영상 하나하나), "촬영함 단계 넣고 직접 체크".

## 왜

지금 홈의 진행 막대는 카테고리 전체를 한 번 훑는 기준이다. 기획안을 하나 만들면 그 단계가 계속 ✓라서, 지금 만들고 있는 영상이 어디쯤인지 보이지 않는다(실제 작업 폴더 travel: 다섯 단계 중 진단만 남음, 기획안 6개 모두 콘티까지 있음, 1개는 자막 영상까지). 설명 세 줄·막대·다음 할 일 버튼이 비슷한 무게로 흩어져 "다음에 뭘 할지"가 한눈에 안 들어온다.

## 목표

- 홈을 열면 맨 위에서 다음에 할 일 하나를 바로 본다.
- 만들고 있는 영상(기획안)마다 어느 단계까지 왔는지와 그 영상의 다음 단계를 본다.
- 촬영은 사용자가 직접 체크한다(파일로는 알 수 없음).
- 카테고리 단계는 한 줄로 남긴다.

## 하지 않는 것

- 업로드·조회수 같은 공개 후 단계(Analytics 연동은 보류 항목).
- 기획안 본문, `## 내 메모` 수정. 촬영 체크는 프런트매터 한 항목만 바꾼다.
- 다른 카테고리의 영상을 섞어 보여 주기(지금 고른 카테고리만).

## 영상별 진행 (기획안 하나 = 영상 하나)

대상: `drafts/*.md` 중 `-conti.md`가 아니고 프런트매터 `category`가 지금 카테고리인 것(현재 `status._drafts`와 같은 기준). 프런트매터가 깨진 md는 목록에서 뺀다.

| 키 | 이름 | 완료 판정 | 필수 |
|---|---|---|---|
| `draft` | 기획안 | 기획안 md가 있음(항상 완료) | 예 |
| `polish` | 다듬기 | 본문에 `## 패키징` 줄이 있음(`/yt-polish` 반영 기록) | 아니오 |
| `conti` | 콘티 | `<기획안 stem>-conti.md`가 있음 | 예 |
| `filmed` | 촬영함 | 프런트매터 `filmed_at`이 날짜(YYYY-MM-DD) | 예 |
| `captions` | 자막 영상 | `<기획안 stem>-captions.mp4`가 있음 | 아니오 |
| `diagnose` | 진단 | `mine/*.md` 중 프런트매터 `target`이 이 기획안의 작업 폴더 기준 경로인 것이 있음. **(제 판단)** 비교 전에 역슬래시를 `/`로, 앞의 `./`를 지운다(대소문자는 그대로). 깨진 mine md는 건너뛴다 | 예 |

- 영상의 "다음 단계" = 순서상 아직 안 한 **필수** 단계 중 첫 번째. 선택 단계는 다음 단계가 되지 않는다(건너뛰어도 됨).
- 필수 단계를 모두 마친 영상은 "완료".
- 진행 정도 = 마친 필수 단계 수.

### 다음 단계별 행동

| 다음 단계 | 버튼 글 | 이동/동작 |
|---|---|---|
| `conti` | 콘티 만들기 | `#/conti/<기획안 경로>` (콘티 화면이 기획안 하나를 받아 만든다) |
| `filmed` | 촬영함 체크 | 화면 안에서 바로 체크(아래) |
| `diagnose` | 진단하기 | `#/diagnose/<기획안 경로>` |

기획안 제목을 누르면 `#/draft/view/<경로>`로 간다.

## 촬영함 체크

- 영상 줄의 "촬영함" 단계 표시가 토글 버튼이다(`aria-pressed`). 누르면 체크, 다시 누르면 해제. "촬영함 체크" 다음 단계 버튼도 같은 동작이다.
- 저장: 기획안 프런트매터 `filmed_at: 'YYYY-MM-DD'`(오늘, 로컬 날짜). 해제는 `filmed_at` 키를 지운다. `refstore.update_frontmatter`로 프런트매터만 바꾸고 본문·`## 내 메모`는 그대로 둔다. **(제 판단)** 지금 `update_frontmatter`는 키를 지우지 못하므로 지울 키 목록을 받는 인자(`remove`)를 더한다(기존 호출은 그대로). 프런트매터는 다른 저장 기능과 마찬가지로 다시 직렬화된다(키 순서·따옴표 모양은 바뀔 수 있음, 값과 본문 바이트는 보존).
- 읽기 확인과 쓰기는 한 잠금 안에서 한다(hash 확인과 쓰기 사이에 다른 저장이 끼지 않게, `api_diagnose`의 `WRITE_LOCK` 방식).
- **(제 판단)** 순서는 강제하지 않는다: 콘티가 없어도 촬영함을 체크할 수 있다(사용자가 콘티 없이 찍을 수도 있다). 진행 정도는 순서와 무관하게 마친 필수 단계 수다.
- 동시 수정 방지: 홈 데이터에 기획안 파일의 sha256(`hash`)을 함께 내고, 체크 요청에 그 값을 실어 보낸다. 다르면 `draft_changed`(400, "화면을 연 뒤 기획안이 바뀌었습니다. 다시 불러와 주세요")로 거부하고 화면은 다시 불러오기를 안내한다(`polish.py`와 같은 방식).
- 경로 검증: `drafts/` 바로 아래의 `.md`(`-conti.md` 제외)만 받는다. 작업 폴더 밖·다른 폴더·없는 파일은 거부한다.
- API: `POST /api/drafts/filmed` `{category, path, filmed: bool, hash}` → `{path, filmed_at|null, hash}`(새 hash).
- `filmed_at`은 계산 입력이 아니다(유형화·진단·모티브는 이 값을 읽지 않는다). 설계서 템플릿 설명에 항목을 더한다. `schema_version`은 그대로(선택 항목 추가, 기존 파일은 없음 = 촬영 전).

## 다음 할 일 (맨 위 카드)

1. 완료가 아닌 영상이 있으면: 진행 정도가 가장 큰 영상, 같으면 기획안 날짜가 최근인 것, 그래도 같으면 파일 이름 역순. **(제 판단)** 파일 수정 시각은 쓰지 않는다: 촬영 체크·다듬기 저장이 수정 시각을 바꿔 순서가 튄다. 그 영상의 다음 단계 행동과 짧은 이유를 보여 준다.
   - 이유 예: 콘티 → "기획안을 촬영용 콘티로 바꿔요", 촬영함 → "콘티대로 찍었으면 체크해 두세요", 진단 → "찍은 영상을 아키타입과 비교해 고칠 점을 찾아요".
2. 영상이 없거나 모두 완료면: 지금의 카테고리 단계 기준 다음 할 일(`status._next`, 예: 레퍼런스 더 모으기, 유형화)을 그대로 쓴다.
3. 카테고리 단계가 모두 끝났고 영상도 모두 완료면: "새 기획안 만들기"(`#/draft/new`).

## 화면 배치 (시안: `.superpowers/brainstorm/.../home-progress.html`)

위에서부터:
1. **다음 할 일** 카드 — 왼쪽 파란 막대, "다음 할 일" 작은 머리글, 굵은 한 줄, 이유 한 줄, 오른쪽에 주요 버튼 하나(이 화면의 유일한 `btn-primary`).
2. **만들고 있는 영상** 카드 — 영상 한 줄: 제목(한 줄 말줄임)과 날짜·목표 길이, 단계 점 6개(완료 ✓ 초록, 다음 단계 파란 테두리, 선택 단계 점선), 줄 끝 다음 단계 버튼(보조 버튼). 완료가 아닌 영상을 진행 정도→기획안 날짜→파일 이름 역순으로, 완료 영상은 맨 아래 "완료" 표시. 처음에 3줄, 나머지는 "N개 더 보기" 버튼으로 펼침(펼침 상태는 기억하지 않음).
3. **카테고리 단계** — 한 줄: 카테고리 이름 + 꼬리표 5개(모으기 19 · 유형화 · 기획안 6 · 콘티 6 · 진단 기록 0; 숫자는 `status`의 각 단계에 `count` 정수 필드를 더해서 쓴다, 유형화는 숫자 없음. 진단 숫자는 카테고리 전체 진단 기록 수라 영상별 진단과 기준이 달라 "진단 기록"이라고 쓴다), 끝난 것은 초록, 지금 단계는 차콜(`--pick-bg`), 오른쪽에 단계 설명(예: "레퍼런스 10개 이상 · 3단계"). 지금의 설명 세 줄(`stage_text`)은 이 한 줄로 대신한다.
4. **오늘 미션 · 최근 결과물** — 두 칸, 지금 내용 그대로, 작게.

- 여러 카테고리: 지금처럼 고른 카테고리만 위 1~3을 그린다. 다른 카테고리는 3번 한 줄씩만 아래에 둔다(누르면 그 카테고리로 바꿈).
- 작업 폴더가 아님 / 카테고리 없음 / 불러오기 실패 화면은 지금 그대로.
- 좁은 화면: 영상 줄은 제목 위, 단계 점과 버튼이 아래 줄로 내려간다. 단계 점 이름은 작게라도 항상 보인다.
- 접근성: 단계 점 묶음은 목록(`ol`)이고 각 점에 "콘티 완료/다음 단계/아직/선택" 글이 화면 읽기용으로 붙는다. 촬영함 토글은 버튼(`aria-pressed`)이고 이름은 "<제목> 촬영함".

## 데이터 (`GET /api/status` 확장)

카테고리 항목에 `videos`를 더한다(지금 고른 카테고리뿐 아니라 응답의 모든 카테고리에 계산해도 되고, 비용이 크면 `?category=` 지정 시에만 — 빌더 판단).

```
videos: [{
  path: "drafts/2026-10-25-....md",
  title,        // 프런트매터 title(글자로), 없으면 파일 이름(stem)
  date,         // 프런트매터 date(YYYY-MM-DD 앞 10자), 없으면 파일 이름 앞 YYYY-MM-DD, 그것도 없으면 null
  target_sec,   // 프런트매터 target_sec(유한한 양수만), 없으면 null
  steps: [{key, done: bool, optional: bool}],   // 위 표 순서 6개
  next: "conti" | "filmed" | "diagnose" | null,  // null = 완료
  progress: int,                                  // 마친 필수 단계 수
  filmed_at: "YYYY-MM-DD" | null, hash
}]
```
`next_action` (카테고리별): `{kind: "video", path, step}` 또는 `{kind: "category", text, menu}` 또는 `{kind: "new_draft"}`.

## 테스트로 지킬 것

- 단계 판정: 패키징 줄, 콘티·자막 파일, `filmed_at` 날짜/빈 값/날짜 아닌 값, `mine` target 일치(다른 기획안 target, 깨진 mine md는 무시).
- 다음 단계·진행 정도·정렬·맨 위 다음 할 일 고르기(동점은 기획안 날짜 → 파일 이름 역순).
- 촬영 체크 API: 체크/해제 왕복, hash 불일치 거부, 경로 탈출·`-conti.md`·없는 파일 거부, 본문·`## 내 메모` 바이트 보존, 다른 프런트매터 키 보존.
- 화면: 다음 할 일 카드에 주요 버튼 하나, 촬영 토글 `aria-pressed`, 더 보기, 다른 카테고리 한 줄.

## 관련 규칙

- 계산 입력은 md 프런트매터뿐, 본문과 `## 내 메모`는 덮어쓰지 않는다(CLAUDE.md).
- 사이드바·카드 작업에서 정한 토큰(`--pick-bg`, `--elev-1`, `--chip`)을 쓴다. 강조색은 이 화면의 주요 버튼 하나와 다음 단계 표시에만.
