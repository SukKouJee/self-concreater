# 장면 단위 콘티 + 내용 맞춤 레퍼런스 사진 — 설계

날짜: 2026-10-29 · 상태: 초안(사용자 확인 전)

## 왜

사용자(1인 크리에이터, 여행·동네 롱폼 위주)가 콘티를 보고 **무엇을 찍을지 상상이 안 된다**고 했다. 실제 작업 폴더의 콘티 5개를 열어 본 결과 원인은 두 가지다.

1. **컷이 "편집 컷"이라 같은 장면이 반복된다.** `yt-draft`가 "샷 수 = 편집 컷 수"이고 컷 길이는 레퍼런스 편집 속도(2~4초)를 따르게 해서, 15분 롱폼이 357~469컷이 된다. AI는 섹션마다 장면 4~6개를 만들고 돌려 가며 채운다(예: "공원 산책로 걷기" 11번). 대사는 몇 글자씩 잘려 순서대로 붙어서 "부대찌개거리."가 "맛 한마디" 컷에, "이건 먹어야죠."가 "끓는 찌개" 컷에 붙는 식으로 말과 장면이 어긋난다.
2. **그림과 사진이 내용과 무관하다.** 도식(`conti.sketch`)은 샷 크기마다 고정 그림이다(클로즈업 = 라면 그릇과 젓가락, 탑뷰 = 접시 4개). 참고 사진(`conti.match_frames`)은 컷마다 붙지만 샷 크기·섹션만 같으면 고르기 때문에 "시장 입구" 컷에 지하철 사진이 나올 수 있다.

## 사용자가 정한 것

- 컷마다 **레퍼런스 장면 사진**이 붙어서 그것만 보고 찍을 수 있어야 한다.
- 내용이 맞는 사진이 없으면 **구도가 비슷한 사진이라도 붙인다**(표시로 구분).
- 반복 컷은 **찍을 장면 하나 = 컷 하나로 합친다**. 그 장면의 길이와 대사는 통째로 그 컷에 둔다.
- **기존 콘티도 자동으로 합친다.**

## 목표

- 콘티의 단위가 "찍을 장면"이 된다. 장면마다 행동·가이드·길이(초)·그 구간의 이어진 대사.
- 장면마다 내용이 가장 비슷한 레퍼런스 사진, 없으면 구도가 비슷한 사진(표시: "구도만 참고").
- 기존 콘티 5개(그리고 이후 사용자의 다른 콘티)를 장면 단위로 합친다. 사용자가 고친 가이드·대사·고정 사진을 잃지 않는다.

## 하지 않을 것(non-goals)

- AI 이미지 생성(그림을 새로 그리기)은 하지 않는다. 사진은 사용자가 모은 레퍼런스 프레임에서만 고른다.
- 편집 컷 리스트(2초마다 자르기)를 따로 만들지 않는다. 편집은 CapCut에서 한다. 편집 속도는 장면 메모로만 남긴다.
- 레퍼런스를 새로 다운로드하지 않는다(CLAUDE.md: 다운로드 영상은 프레임 추출 직후 삭제). 이미 저장된 대표 프레임(`workspace/frames/`)만 쓴다.

## 실패로 볼 것(anti-goals)

- 합친 뒤 사용자가 고친 대사·가이드가 사라지거나, 대사 순서가 원래 섹션 대사와 달라지는 것.
- 사진이 "근사"인데 맞는 것처럼 보이는 것(구분 표시 없이).
- 사진 설명을 만들 때마다(콘티 렌더할 때마다) Claude를 다시 부르는 것. 설명은 프레임당 한 번.

## 제약

- CLAUDE.md: 의미 해석(사진 설명, 장면 합치기의 대사 재배치)은 Claude, 계산·저장은 스크립트. AI 출력은 제안이고 저장 전에 사용자 확인. md 본문과 `## 내 메모`는 덮어쓰지 않는다. 비용: 프레임은 장면당 1장, 영상당 최대 40장(이미 저장된 것만 씀).
- 콘티 이력(`conti_history`)과 컷 id(`ensure_ids`), 촬영 영상 판정(`workspace/footage_match/<stem>.json`, 컷 id 기준)이 컷 단위에 걸려 있다.

## 설계

### A. 기획안·콘티 규칙을 장면 단위로

- `skills/yt-draft/SKILL.md` 3절: "샷 하나 = 편집 컷 하나 / 같은 샷 반복은 하나씩 다 적는다"를 **"샷 하나 = 찍을 장면 하나, 같은 장면을 반복해 적지 않는다"**로 바꾼다. 샷 길이는 그 장면을 찍어 쓸 분량(롱폼은 대개 10~60초, 쇼츠는 1~5초). 아키타입 평균 컷 길이는 장면별 편집 메모 근거로만 쓴다.
- `skills/yt-conti/SKILL.md` 2·3절: 장면 하나 = 컷 하나. `line`은 그 장면에서 하는 말 전체(섹션 컷 `line`을 이으면 섹션 `text`, 기존 규칙 유지). `guide`에 편집 메모를 붙일 수 있다(예: "편집: 2~3초마다 끊기").
- 반복 판단은 A·B 모두 같은 규칙: **같은 섹션 안에서 `action`이 같은 컷**(연속이 아니어도). 쇼츠도 예외 없음. 다른 장면은 짧아도 그대로 컷. (내 판단)
- 기획안 md는 고치지 않는다(본문 덮어쓰기 금지). 그래서 `yt-conti`는 예전 기획안의 반복 샷을 받아도 **같은 규칙으로 한 장면으로 묶어서** 콘티를 만든다. "다시 만들기"를 해도 반복이 돌아오지 않는다. (내 판단)
- 컷 길이 상한: 지금 `MAX_CUT_SEC`가 장면 길이를 막으면 올린다(값은 만드는 사람이 정함, 롱폼 장면 60초 이상을 허용).
- `line_too_long` 경고는 그대로 의미가 있다(말 속도 × 길이).

### B. 기존 콘티 합치기

- **같은 섹션 안에서 `action`이 같은 컷을 한 장면으로 합친다**(연속이 아니어도: 지금 콘티는 A B C D A B C D 식으로 돈다). 장면 위치는 첫 등장 자리, 길이는 합, 대표 `size`/`angle`은 첫 컷 것.
- 대사: 합치면 섹션 대사 순서가 깨진다(A가 1·5·9번째 조각을 가짐). 그래서 **원래 컷 순서대로 지금의 `line`을 이은 글**(사용자가 고친 대사 그대로)을 합친 장면들에 Claude가 다시 나눠 배정한다(의미 판정). 글자는 바꾸지 않고 나누는 자리만 정한다 — 장면 `line`을 이으면 그 글과 같아야 한다(검증). 섹션 `script.text`는 그 이은 글로 맞춘다(지금도 컷 대사를 고치면 retime이 하는 일). 장면 순서를 대사 흐름에 맞게 바꿀 수 있다(같은 섹션 안에서만). (내 판단: 고친 대사를 잃지 않는다)
- 사용자 편집 보존: 합쳐지는 컷들의 `guide`·`caption`·`sfx`가 서로 다르면 겹치지 않게 이어 붙인다(중복 제거). `ref_frame`(고정 사진)은 첫 번째 고정된 것을 쓴다. 컷 id는 합쳐지는 컷 중 첫 컷의 id를 남긴다.
- 촬영 영상 판정: **사용자 판정만 옮긴다**(고른 구간·못 찍음 — 합쳐지는 컷 중 첫 사용자 판정을 남은 장면에). AI 판정은 버려서 다음 맞추기에서 새 장면 기준으로 다시 판정. 장면 길이와 고른 구간 길이가 달라도 그대로 둔다(사용자가 고른 것). (내 판단)
- 흐름: 콘티 화면에 "장면으로 합치기" → 미리보기(전/후 컷 수, 섹션별 장면 목록과 대사) → 저장. 저장 전에 이력에 자동 스냅샷("합치기 전")을 남겨 되돌릴 수 있게 한다. 반복이 없는 콘티는 "합칠 장면이 없어요".
- CLI도 같은 기능을 낸다(`ytc conti merge <conti.md>` 미리보기 JSON, `--apply`로 저장). 이름은 만드는 사람이 기존 conti CLI 관례에 맞춘다.
- "자동으로 합쳐 달라"의 뜻: 사용자가 장면을 손으로 묶지 않아도 된다는 것. 저장 전 확인(CLAUDE.md)은 그대로 둔다. 기존 5개는 이 기능으로 하나씩 미리보기 → 저장.

### C. 레퍼런스 사진 설명(한 번만)

- 레퍼런스 대표 프레임마다 **무엇이 찍혔는지 한 줄 설명**(장소·피사체·행동, 예: "시장 골목, 사람 많음, 눈높이 와이드")과 샷 크기·앵글을 만든다. 기존 `yt-shots` 분류를 확장한다: 라벨에 `desc`를 더하고, 지금 영상당 표본(`frames.shots_sample`)만 보던 것을 **영상의 저장된 대표 프레임 전부**(영상당 최대 40장)로 넓힌다. 이미 라벨이 있는 프레임은 `desc`만 채운다.
- 저장: `workspace/shots/<id>.json` 라벨에 `desc` 필드(기계용 원본층, 이미 있는 파일). 영상 md 프런트매터에는 쓰지 않는다(계산 입력 아님).
- 비용: 지금 작업 폴더 기준 약 840장. 호출당 8장이면 약 105번, 한 번만. UI의 레퍼런스 화면이나 콘티 화면에서 "사진 설명 만들기"(진행률·멈추기, 기존 jobs 패턴)로 돌린다. 새 레퍼런스를 추가할 때 분석과 같이 돌릴지(옵션)는 만드는 사람이 기존 "샷 분류도 함께" 옵션에 묶는다.

### D. 장면에 사진 고르기

- 순서: (1) 사용자가 고정한 사진 → (2) **내용 맞춤**: 장면의 `action`+`guide`와 프레임 `desc`의 유사도가 기준 이상인 것 중 가장 높은 것(같은 카테고리 레퍼런스) → (3) **구도 맞춤**: 지금의 샷 크기(+섹션) 매칭.
- 내용 맞춤은 **Claude가 글로만 고른다**(사진은 보지 않음, 이미 만든 `desc` 목록과 장면 목록을 주고 장면마다 프레임 하나 또는 "없음"). 콘티를 만들 때·"사진 다시 고르기"를 누를 때만 부르고(합칠 때는 부르지 않고 묶음의 첫 번째 `ref_auto`를 이어받는다. 다시 맞추려면 "사진 다시 고르기"), 결과를 컷에 `ref_auto`(프레임 경로 + 맞춤 종류)로 저장한다. 렌더할 때는 저장된 값만 쓴다(Claude 안 부름). 고른 프레임 파일이 없어졌거나 `ref_auto`가 없으면 구도 맞춤으로. 이유: 사용자가 쓴 장면 설명과 Claude가 쓴 사진 설명은 단어가 잘 안 겹쳐 글자 유사도만으로는 품질이 안 나온다. 장면 수가 많으면 묶음으로 나눠 부른다(120장면씩, 후보는 짧은 키 → `desc | size | angle` 한 줄로 보내고 Claude는 키로 답한다). 반복 컷이 남은 콘티는 고르지 않는다(`merge_first`, 만들기 작업은 경고만). 저장은 파일 해시를 요구하지 않고, 고를 때와 action·guide·size가 같은 장면에만 쓴다. 뒤 묶음이 실패해도 앞 묶음 결과는 저장한다. 컷의 action·guide·size를 고치면 그 컷의 `ref_auto`는 지운다(구도 맞춤으로). (내 판단)
- 후보는 같은 카테고리 레퍼런스의 프레임만.
- 같은 사진이 여러 장면에 반복되지 않게 덜 쓴 것 우선(기존 `used` 규칙 유지).
- 표시: 내용 맞춤은 "참고", 구도 맞춤은 **"구도만 참고"**, 고정은 "참고(고정)". 사진 아래 프레임 설명 한 줄을 보여 준다(무엇을 찍은 사진인지).
- 도식(`sketch`)은 사진이 하나도 없을 때만 보인다(레퍼런스가 없는 카테고리 등). 그 외에는 HTML·UI에서 빼서 사진을 크게.
- UI 콘티 편집기의 사진 바꾸기(지금 있는 기능)는 그대로 쓰되, 후보 목록에 프레임 설명을 같이 보여 준다.
- 사진 설명이 아직 없는 카테고리(또는 일부만 있음)면 콘티 화면에 안내: "레퍼런스 사진 설명을 만들면 장면에 맞는 사진이 붙어요 (사진 N장, 약 M분)" + 만들기 버튼. 설명이 끝나면 "사진 다시 고르기"를 권한다. 합치기는 설명 없이도 할 수 있다(사진은 구도 맞춤으로). (내 판단)

### E. 화면

- 스토리보드 HTML과 UI 콘티 카드: 사진을 주 그림으로(도식 대신), 사진 아래 "참고 · <설명>" 또는 "구도만 참고 · <설명>". 장면 길이가 길어지므로 카드에 "약 25초" 같은 길이를 눈에 띄게.
- 머리말 문구 "컷 N개 · 평균 N초"는 "장면 N개"로.

## 만드는 사람에게 맡기는 것

- 내용 맞춤 묶음 크기, `MAX_CUT_SEC` 새 값, 합치기 CLI 이름, 촬영 영상 판정 이전 규칙의 세부, 사진 설명 job의 UI 위치.
- 합치기에서 `action`이 아주 비슷하지만 글자가 다른 컷(예: "벤치에 앉아 쉬며 한마디" vs "벤치에서 쉬기")을 같은 장면으로 볼지 — 이번에는 **글자 정규화 후 같은 것만** 합친다(내 판단, 오합치기가 덜 위험).

## 관련 교훈

- 촬영 영상 매칭에서 Claude 이미지 상한(호출 8장)과 묶음 실패 처리 패턴(`footage_match`)을 사진 설명 job에 재사용할 수 있다.
- 콘티 편집기의 컷 id 재매핑(`remapByCutId`)은 합치기 뒤 UI 초안 보존에 필요하다(합친 뒤 편집기 새로고침).
