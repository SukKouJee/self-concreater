# 촬영 영상 ↔ 콘티 매칭 — 설계

날짜: 2026-10-27 · 로드맵 3번(1 콘티 이력, 2 컷 편집은 main에 들어감)

## 왜

사용자 말: "내가 잔뜩 영상을 찍어 왔는데 거기에서 콘티에 맞는 장면, 맥락이 나오면 해당 파일, 어디 부분 등을 indexing 해줄 수 있어?", "token이 많이 들면 저화질로 변환해서 보고 알려줘도 돼".
대사는 대충 따르고 현장에서 넣고 빼므로, 글자가 같은지가 아니라 **뜻**으로 맞춰야 한다.

## 사용자가 정한 것

- 촬영본: 폰 클립 수십 개(한 번에 30개·2시간쯤), 앞으로 액션캠 4K 25~30fps도. PC에 **날짜별 폴더**로 복사해 둔다. 편집은 CapCut.
- 영상 하나를 **며칠에 걸쳐** 찍는다 → 콘티 하나에 폴더 여러 개를 시간이 지나며 더한다.
- **촬영 중간중간 넣어서 남은 컷을 확인**한다(첫 쓰임새). 남은 컷은 **현장에서 폰으로도** 본다.
- 결과는 **두 가지 다**: 컷별 위치 목록(파일 + 시간)과 컷별로 잘라 낸 파일.
- 컷마다 후보 2~3개, 사용자가 고른다. **확실하면 자동으로 '찍음'**(언제든 바꿀 수 있음).
- 콘티에 없는 좋은 장면은 새 컷으로 제안한다.
- 비용: 저화질 변환·장면 나누기·받아쓰기는 로컬, 대사 컷은 글자로, 대사 없는 컷만 저화질 장면 모음 이미지를 AI가 본다.

## 지켜야 할 것

- **원본 영상은 읽기만** 한다(옮기기·고치기·지우기 없음). 만든 것은 작업 폴더 안에만 쓴다.
- AI 출력은 제안이다: 자동 '찍음'은 판정 표시일 뿐 콘티 md를 바꾸지 않는다. 콘티에 컷을 넣는 것은 사용자가 누를 때만(기존 `edit_cuts` insert → 이력 auto).
- `## 내 메모`·본문 불변. 로컬 UI만, 외부 주소 없음(폰용 HTML도 한 파일, 외부 자원 없음).
- 무거운 일은 하나씩(워커 하나). 링크 자동 수집 금지와는 무관(사용자 파일만).
- 디자인: shadcn 토큰·규칙. 사용자 문구 한국어.
- CLAUDE.md의 "프레임은 장면당 1장, 영상당 최대 40장"은 레퍼런스 분석의 비용 규칙이다. 촬영본은 로컬에서 장면당 사진 여러 장을 뽑되(비용 0), **AI에 보내는 이미지는 호출당 8장, 콘티 한 번 처리에 최대 120장**으로 따로 묶는다(내 판단). 설계서(`yt-coach-plugin-design.md`)에 이 구분을 적는다.

## A. 폴더 연결과 처리

- 콘티 편집 화면에 `촬영 영상` 영역(접기). `폴더 더하기`(경로 입력 — 로컬 UI라 파일 선택 창 대신 경로 붙여 넣기, 내 판단), 연결된 폴더 목록(파일 수·총 길이·처리 상태), `빼기`(연결만 끊고 처리 결과는 남김).
- 영상 확장자: .mp4 .mov .m4v .mkv(대소문자 무시). 하위 폴더는 보지 않는다(내 판단).
- 처리는 파일 단위로 한 번만: (경로, 크기, 수정 시각)이 같으면 건너뛴다. 새 파일만 처리.
- 파일 하나의 처리(로컬, 비용 0):
  1. 저화질 사본 대신 **필요한 것만 뽑는다**: 장면 경계(기존 OpenCV 컷 탐지, 360p로 디코딩), 장면마다 대표 사진 4~6장(작은 JPEG), 장면 모음 이미지(사진들을 한 장에 이어 붙임 — AI용).
  2. 음성 받아쓰기: 기존 `faster-whisper`(선택 설치, CPU). 없으면 그 안내를 띄우고 대사 맞추기 없이 사진만으로 진행.
  - 저장: `workspace/footage/<파일 지문>/`(scenes.json, transcript.json, frames/). 지문 = 경로 해시 + 크기 + 수정 시각.
- 진행 카드: 레퍼런스 추가와 같은 모양(원형 %, 남은 시간, 지금 파일). 멈추기 가능. 2시간 분량은 수십 분 걸릴 수 있다고 미리 알린다.

## B. 맞추기와 판정

- 대상: 콘티 컷마다 대사(line)·가이드·장면 설명(action)·샷 크기.
- 1단계(로컬, 비용 0): 받아쓴 구간과 컷 대사를 글자 유사도로 비교해 후보를 좁힌다.
- 2단계(AI): 컷별 후보(장면 구간 + 받아쓴 말 + 모음 이미지)를 묶어 Claude에게 "이 컷에 가장 맞는 구간 2~3개와 확신도(높음/중간/낮음)"를 묻는다. 대사가 있는 컷은 글자만, 대사 없는 컷만 모음 이미지를 붙인다(영상당·호출당 이미지 수 상한, 내 판단: 호출당 8장).
- 판정:
  - `찍음(자동)`: 확신도 높음인 후보가 있음 → 그 후보를 선택한 상태.
  - `확인 필요`: 중간 이하 후보만 → 후보 2~3개, 사용자가 고르기 / `못 찍음`으로 바꾸기.
  - `아직 못 찍음`: 후보 없음.
  - 사용자가 바꾼 판정은 다음 처리에서 덮어쓰지 않는다.
- 저장: `workspace/footage_match/<콘티 stem>.json` — 연결 폴더, 컷 id별 판정·선택 구간(파일, 시작, 끝)·후보·사용자 고정 여부. 컷은 **id로** 잇는다(컷 편집·이력과 맞물림). 콘티에서 컷이 지워지면 그 판정은 버린다.
- 새 폴더를 더하면 새 파일만 처리하고, `찍음(사용자 고정)`이 아닌 컷만 다시 맞춘다.

## C. 남은 컷 (첫 쓰임새)

- 영역 머리에 요약: `찍음 18 · 확인 필요 3 · 남은 컷 6`. 필터 버튼으로 남은 컷·확인 필요만 보기.
- 확인 필요 카드: 후보마다 대표 사진, 파일 이름·시간, 받아쓴 말 한 줄, `이걸로`(선택), `재생`(그 구간을 화면 안 `<video>`로 — 로컬 파일을 서버가 범위 요청으로 내줌), 그리고 `못 찍음으로`.
- `폰용 남은 컷 만들기`: `drafts/<기획안>-remaining.html` 한 파일(외부 자원 없음, 스토리보드 HTML과 같은 방식) — 남은 컷과 확인 필요 컷만, 컷마다 번호·섹션·샷 크기 도식·참고 프레임·대사·가이드. 만든 시각과 "찍음 18/27"을 맨 위에. 폰으로 옮기는 방법은 사용자가 평소대로(카톡·드라이브 등).

## D. 콘티에 없는 좋은 장면

- 어느 컷에도 선택되지 않은 장면 중, 말이 있거나(받아쓰기 길이) AI가 "쓸 만함"으로 표시한 장면을 `새 컷 후보`로 모은다(AI 판단은 B 2단계 호출에 같이 묻는다 — 추가 호출 없음, 내 판단).
- 카드: 사진, 파일·시간, 받아쓴 말, AI가 제안한 컷 대사·가이드·샷 크기, `이 컷 뒤에 넣기`(컷 선택 → 기존 `edit_cuts` insert, 이력 auto, 그 새 컷은 이 구간으로 `찍음(사용자 고정)`).
- `숨기기`로 후보에서 뺀다(다시 나오지 않음).

## E. 편집 준비

- 위치 목록: 화면 표(컷 번호·섹션·파일·시작–끝·판정) + `CSV 받기`(`drafts/<기획안>-footage.csv`).
- 잘라 낸 파일: `컷 파일 만들기` → `drafts/<기획안>-cuts/NN_<원본 이름>.mp4`(NN = 컷 번호 두 자리). 다시 압축하지 않고 잘라 원본 화질 유지(PyAV 재포장). 키프레임 때문에 시작이 조금 앞당겨질 수 있다고 안내(최대 몇 초). 같은 폴더를 다시 만들면 덮어쓴다(그 폴더는 이 기능 전용).
- 선택된 구간이 있는 컷만 대상. 진행 카드로 보여 준다.

## F. 빌더 질문에 대한 결정 (2026-10-27, 모두 내 판단 — 사용자가 결정을 맡김)

1. **AI 엔진·이미지**: 기존 `llm.ask_validated(..., files=[...])`를 그대로 쓴다(claude-cli·anthropic-api 둘 다 지원하는 경로). 장면 모음 이미지 한 장 = 이미지 1장으로 센다. 호출당 8장, 콘티 한 번 처리에 120장 상한. 상한에 걸려 못 본 컷은 `확인 필요`로 두고 이유("사진 상한으로 AI가 보지 못함")를 단다.
2. **동시 실행**: 새 작업 종류 `footage`(처리·맞추기)와 `footage_clips`(컷 파일 만들기)는 각각 하나만. CPU를 많이 쓰므로 **레퍼런스 수집(collect)과 동시에 돌지 않는다**: 한쪽이 돌면 다른 쪽 시작을 `ScriptError("busy", "레퍼런스 분석이 끝난 뒤 시작해 주세요")`(또는 반대 문구)로 거절. 중단·재시작 뒤에는 파일 지문 캐시로 **이어서** 한다(끝난 파일은 건너뜀).
3. **HEVC·4K**: PyAV로 먼저 디코딩하고(디코더 단계에서 줄여 받아 OpenCV보다 2~8배 빠름 — Task 1 측정, 2026-10-27 변경), 못 열거나 한 장도 못 읽거나 읽다 오류가 나면 OpenCV로 다시 해 본다. 파일 잠김·드라이브 분리(OSError)는 `다시 시도`로 두고 캐시하지 않는다. 둘 다 실패한 파일은 `읽을 수 없음`(이유 표시)으로 두고 건너뛴다. ffmpeg 설치를 요구하지 않는다. 장면 탐지는 360p 이하로 줄이고 초당 5프레임만 본다(속도). 목표: 2시간 분량 로컬 처리 60분 이내(이 PC 기준, 받아쓰기가 대부분) — 넘으면 보고하고 원인 기록.
4. **컷 파일**: 키프레임부터 영상·소리를 함께 재포장(다시 압축 없음)이 기본. 재포장이 실패한 파일만 그 구간을 PyAV로 다시 압축(H.264)해서 만든다. 결과 목록에 "다시 압축함" 표시.
5. **원본 재생 서빙**: 브라우저는 경로가 아니라 **파일 지문 id**로 요청한다(`/api/footage/media/<id>`). 서버는 id를 연결된 폴더 안의 실제 파일로만 풀고(실제 경로를 다시 확인, 링크 탈출 거부), Range 요청을 지원한다. 폴더를 `빼기`하면 그 폴더 파일은 곧바로 내주지 않는다.
6. **판정과 콘티 이력**: 컷이 지워져도 그 id의 판정은 **지우지 않고 숨긴다**(되돌리기·이력 복원으로 같은 id가 돌아오면 판정도 돌아옴). 화면·내보내기는 지금 콘티에 있는 컷만 쓴다.
7. **원본이 사라짐**(이동·삭제·이름 변경·외장 드라이브 분리): 처리 결과는 남기고, 그 파일을 가리키는 후보·선택에 `원본 없음`을 표시한다. 컷 파일 만들기는 그 컷을 건너뛰고 이유를 보인다. 같은 파일이 같은 폴더에 다시 나타나면(같은 지문) 자동으로 되살아난다.
8. **받아쓰기**: 기존 `scripts/stt.py`의 모델 설정(`YT_STT_MODEL`, 기본 small, CPU int8)을 재사용하고 언어는 한국어(`ko`) 고정. 로컬 파일을 받아쓰는 함수를 stt.py에 더한다(지금은 레퍼런스용 다운로드 흐름에 묶여 있음).

## 범위 밖

- 원본 영상 편집·이동, 자동 편집(타임라인 생성), CapCut 프로젝트 파일 직접 만들기, 클라우드(구글 포토 등) 연동, 동시 여러 콘티 처리.

## 빌더에게 맡기는 것

- 장면 대표 사진 수·크기, 글자 유사도 방식, AI 호출 묶음 크기(비용 상한 안에서).
- 범위 요청(HTTP Range)으로 로컬 영상 재생을 내주는 방식(작업 폴더 밖 원본을 연결 폴더 목록에 있는 것만 허용).
- 처리 모듈 분리(`scripts/footage.py` 권장).
