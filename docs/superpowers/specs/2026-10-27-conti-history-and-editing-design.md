# 콘티 이력 + 컷 편집 — 설계

날짜: 2026-10-27 · 대상: 콘티(`drafts/*-conti.md`)와 콘티 화면(`#/conti/<path>`)
로드맵: 1 콘티 이력 → 2 컷 편집(이 문서) → 3 촬영 영상 매칭(다음 문서)

## 왜

사용자 말: 대사는 대충 따르고 현장에서 추가·삭제가 있어서 "콘티가 실제로 찍고 나서 변경되는 경우가 있다".
"콘티 기획, 편집 시에 추가·삭제에 대한 git tree같이 관리되었으면", "UI적으로도 넣고 빼는 기능이 용이했으면".
3번(촬영 영상 매칭)에서 찾은 장면을 새 컷으로 넣거나 안 찍은 컷을 빼는 일도 이 두 기능 위에서 한다.

## 사용자가 정한 것

- 이력은 **한 줄**(갈래 없음).
- **자동 이력 + 이름 붙인 이력** 둘 다.
- 자동 이력은 **편집 한 번에 하나로 묶는다**(5분쯤 손을 놓으면 묶음이 닫힘). "다시 만들기"·md 직접 수정은 **그 직전 상태**를 따로 남긴다. 이름 붙인 이력은 누를 때마다.
- 비교: **바뀐 점 목록이 기본 + 나란히 보기 전환**.
- 컷을 넣으면 **영상이 그만큼 길어진다**(목표 대비 차이를 보여 줌). **컷 길이도 고칠 수 있다**.
- 사용자가 맡긴 결정(2026-10-27 "너가 좋은방향 결정해서 진행해줘"): 컷 조작 방식(아래 B절).

## 지켜야 할 것

- `## 내 메모`와 md 본문은 사용자 것이다. 되돌리기·편집은 프런트매터(`script`, `cuts`)와 그로부터 다시 그리는 본문 표만 바꾼다(지금 `update_cut`과 같은 방식: 메모·줄바꿈 보존).
- 계산 입력은 프런트매터뿐. 사용자가 md를 직접 고친 것도 정상 편집이다.
- AI 호출 없음(이 두 기능은 순수 편집·계산).
- 디자인: 2026-10-26 shadcn 규칙, 새 색 토큰 없음.

## A. 콘티 이력

### 저장 위치·형태 (내 판단)
- `workspace/conti_history/<콘티 파일 stem>/` 안에 버전마다 JSON 하나: `<번호 4자리>.json`.
  `{"n", "kind", "name", "at" (ISO 시각), "last_touch", "state": {"script", "cuts", "target_sec"}, "summary": {"cuts", "total_sec", "changed": int}}`.
- `kind`: `created`(콘티 처음 저장), `auto`(편집 묶음), `named`(이름 붙임), `before_recreate`(다시 만들기 직전), `external`(md 직접 수정 감지), `restored`(되돌림).
- 콘티 파일이 휴지통으로 가면 이력 폴더도 같은 휴지통 묶음으로 옮긴다(기존 `move_to_trash`).

### 언제 남기나
- 콘티를 처음 저장할 때 `created`.
- 화면·CLI에서 콘티를 바꿀 때마다(컷 고치기, B절의 넣기·빼기·옮기기·길이): 가장 최근 버전이 `auto`이고 `last_touch`가 5분 안이면 그 버전의 `state`를 새 상태로 **덮어쓰고** `last_touch`를 갱신, 아니면 새 `auto` 버전.
- "다시 만들기"로 저장하기 직전: 지금 상태를 `before_recreate`로 남기고, 저장 뒤 `created`.
- 콘티를 불러올 때(`GET /api/conti`), 파일의 상태가 가장 최근 버전의 `state`와 다르면 `external`("md 직접 수정")로 지금 상태를 남긴다. 이력이 하나도 없는 기존 콘티는 처음 불러올 때 `created`를 만든다.
- 이름 붙이기: 지금 상태를 `named` + 이름으로 남긴다(묶음과 무관, 누를 때마다). 이름 후보: 기획 완료, 촬영 후, 편집 중, 직접 입력(1~30자).
- 되돌리기: 고른 버전의 `state`를 파일에 쓰고 `restored`("되돌림: <버전 이름 또는 시각>")로 남긴다. 되돌리기 직전 상태는 이미 가장 최근 버전이라 다시 되돌릴 수 있다.

### 비교
- 컷마다 오래 남는 `id`가 있어야 넣기·빼기·옮기기를 구별할 수 있다 → 컷에 `id`(짧은 무작위 문자열)를 둔다. 없는 콘티는 불러올 때 붙이고 `schema_version`을 3으로 올린다(마이그레이션: id만 추가).
  `id`가 없는 옛 이력 상태끼리는 위치로 맞춘다.
- 바뀐 점 목록(기본): `컷 3 대사: 「…」 → 「…」`, `컷 7 삭제`, `컷 9 새로 생김(본문)`, `컷 4 → 6으로 옮김`, `컷 2 길이 4초 → 6초`, `총 길이 15:00 → 15:08`. 필드: line, guide, caption, sfx, size, sec, section, 순서.
- 나란히 보기: 두 버전의 컷 목록을 양옆에(섹션 머리 포함), 바뀐 칸은 강조, 빠진 컷은 회색 빈 줄, 새 컷은 표시.
- 비교 대상: 아무 두 버전, 또는 한 버전과 지금.

### 화면
- 콘티 편집 화면 머리에 `이력` 버튼 → 오른쪽 패널(좁은 화면이면 전체 덮개): 최신순 목록. 줄마다 시각, 이름(없으면 `자동`/`처음 만듦`/`md 직접 수정`/`다시 만들기 전`/`되돌림`), 컷 수·총 길이, 바뀐 컷 수.
- 패널 위: `지금 상태에 이름 붙이기`(이름 후보 + 직접 입력).
- 줄을 고르면: `지금과 비교`, `이 버전으로 되돌리기`(확인 한 번: "지금 상태도 이력에 남아 있어 다시 되돌릴 수 있어요"). 두 줄을 고르면 `둘 비교`.

### API (빌더가 다듬어도 됨)
- `GET /api/conti/history?path=` → 버전 목록(state 없이). `GET /api/conti/history/version?path=&n=` → 상태 하나.
- `POST /api/conti/history/name {path, name, hash}`, `POST /api/conti/history/restore {path, n, hash}`(쓰기 전 hash 확인: 다르면 `conti_changed`).
- `GET /api/conti/history/diff?path=&a=&b=`(b 생략 = 지금) → `{changes: [...], left: cuts, right: cuts}`.
- CLI: `python -m scripts.conti history <conti.md>` / `history-name` / `history-restore` (JSON 출력).

## B. 컷 편집

### 길이·시간 계산
- 컷 길이(`sec`)를 고칠 수 있다(0.5~120초, 0.5초 단위 — 내 판단).
- 섹션의 시작·끝은 **그 섹션 컷 길이의 합으로 다시 계산**한다(지금은 draft 섹션 길이와 ±0.3초가 맞아야 검증 통과 → 편집 뒤에는 "컷 합이 곧 섹션 길이"인 계산 방식으로 바꾼다. 처음 만들 때의 검증은 그대로).
- 전체 길이 = 컷 길이 합. 머리에 `목표 15:00 → 지금 15:08 (+0:08)`. `target_sec`(목표)은 바뀌지 않는다.
- 섹션의 전체 대사(`script[i].text`)는 지금처럼 그 섹션 컷 대사를 이어 붙여 다시 만든다.

### 조작 (내 판단 — 사용자가 맡김)
- 컷 목록은 섹션 머리(섹션 이름 · 시작–끝)로 나뉜다.
- **순서 바꾸기**: 왼쪽 손잡이(⋮⋮)를 끌어 놓기. 다른 섹션에 놓으면 그 섹션 소속이 된다. 키보드: 컷을 고른 뒤 `위로`·`아래로` 버튼(섹션 경계를 넘으면 소속이 바뀐다). 마우스 없이도 모든 조작이 된다.
- **넣기**: 컷 사이에 마우스를 올리면(키보드 포커스에도) `＋ 여기에 컷 넣기`. 빈 컷(샷 크기 미디엄, 4초, 가이드 "가이드를 적어 주세요" 같은 기본값은 내 판단)을 만들고 오른쪽 편집 칸으로 포커스.
- **⋯ 메뉴**: 위에 넣기, 아래에 넣기, 복제, 삭제.
- **빼기**: 바로 지우고 `컷 7을 지웠습니다 · 되돌리기` 알림(8초). 되돌리기는 그 삭제만 되돌린다(이력 묶음 안에서).
- 편집 칸: 기존 대사·가이드·자막·효과음·참고 프레임 + **길이(초)**, **샷 크기**(정해진 어휘 선택).
- 번호는 항상 위에서부터 1, 2, 3…으로 다시 매긴다. 참고 프레임 고정(`ref_frame`)·장면 후보는 컷 `id`를 따라간다.
- 동시 편집 보호: 지금처럼 파일 hash를 보내고 다르면 `conti_changed`("파일이 밖에서 바뀌었습니다 — 다시 불러오기").
- 섹션이 비게 되는 삭제·이동은 막는다(C절 1). 섹션을 새로 만들거나 지우는 기능은 이번 범위 밖.

### API (빌더가 다듬어도 됨)
- `POST /api/conti/cuts {path, hash, op, ...}`: `op` = `insert {at, section?, cut?}`, `delete {id}`, `move {id, to, section?}`, `duplicate {id}`, `update {id, fields}`(기존 `/api/conti/cut`의 필드 + sec, size).
  응답은 지금 `GET /api/conti`와 같은 모양 + 새 hash. 모든 op는 A절 자동 이력을 남긴다.
- 기존 `POST /api/conti/cut`은 `update`로 이어 준다(호환).

## C. 빌더 질문에 대한 결정 (2026-10-27, 모두 내 판단 — 사용자가 결정을 맡김)

1. **빈 섹션은 만들지 않는다.** 섹션의 마지막 컷은 지우거나 다른 섹션으로 옮길 수 없다(버튼을 끄고 이유: "섹션에 컷이 하나는 있어야 해요"). B절의 "빈 섹션 허용"을 이것으로 바꾼다. 그래서 기존 `validate`의 "섹션마다 컷 하나 이상" 규칙은 그대로다.
2. **편집 뒤 섹션 시간의 원본은 콘티 프런트매터**다. 편집할 때마다 `script[i].start/end`를 컷 길이 합으로 다시 쓰고(뒤 섹션은 밀림), 이후 검증·SRT·HTML은 지금 `render`처럼 프런트매터 시간을 기준으로 한다. 기획안(draft) 섹션 시간과 달라져도 된다. `target_sec`과 `format`은 처음 만들 때 값을 유지한다(편집으로 바뀌지 않음).
3. **새 컷 기본값**: `size: "미디엄"`, `sec: 4`, `action: "새 컷"`, `guide: "촬영 지시를 적어 주세요"`, 나머지 빈 값. 편집 칸에 `장면 설명`(action) 칸도 보인다(비울 수 없음).
4. **컷 `id`**: `validate`는 들어온 `id`를 그대로 보존하고 없으면 붙인다. `n`은 계속 파일에 남고 항상 다시 매긴다. API는 `id`를 기본으로, `n`도 받는다(그 순간 파일 기준으로 풀고 hash가 맞아야 쓴다 — 낡은 화면의 `n`은 hash에서 걸린다). id를 처음 붙이는 일은 불러올 때 한 번 파일에 쓴다(메모·줄바꿈 보존). `schema_version` 3.
5. **자동 묶음 덮어쓰기는 가장 최근 버전의 `kind`가 `auto`일 때만**. `restored`·`named`·`external` 뒤의 편집은 새 `auto`를 연다.
6. **`external` 감지는 상태만 비교**: `script`(label·text·start·end를 소수 둘째 자리로), `cuts`(id를 뺀 필드), `target_sec`. 메모·본문만 바뀐 것은 이력에 남기지 않는다. id를 처음 붙이는 쓰기는 external로 치지 않는다.
7. **산출물이 낡으면 알린다**: 콘티가 SRT·자막 영상 파일보다 나중에 바뀌었으면 SRT·자막 영상 칸에 "콘티가 바뀌었어요 — 다시 받아 주세요". 산출물을 지우지는 않는다.
8. **휴지통**: 콘티를 지울 때 `workspace/conti_history/<stem>/` 폴더도 같은 휴지통 묶음으로 옮긴다(`move_to_trash`는 폴더도 옮긴다 — 레퍼런스 삭제에서 이미 씀).
