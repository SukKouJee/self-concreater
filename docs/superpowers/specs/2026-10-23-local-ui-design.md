# yt-coach 로컬 UI — 1차 설계

- 날짜: 2026-10-23
- 상태: 승인 (2026-10-23)
- 대상 저장소: `nahon-creater` (yt-coach 플러그인)

## 1. 의도와 이유

지금 yt-coach는 슬래시 커맨드(`/yt-coach:*`)와 md 직접 편집으로만 쓴다. 사용자가 실제로 막힌 곳은 두 가지다.

1. **무엇을 할 수 있는지 바로 안 보인다.** 커맨드·스킬 목록과 옵션을 README에서 찾아야 한다.
2. **콘티를 부분적으로 고칠 때 고를 예시가 부족하다.** 컷 하나를 바꾸려면 md를 직접 고치거나 통째로 다시 만들어야 한다. 사용자는 컷마다 **레퍼런스 실제 장면**과 **대사 대안**을 나란히 보고 클릭으로 고르고 싶어 한다.

그래서 yt-coach의 기능을 **내 PC에서만 열리는 웹 화면**으로 쓸 수 있게 한다. 서버에 모아 두는 개인화·중앙화는 이번 범위가 아니다(사용자 명시).

## 2. 목표 · 비목표 · 반목표

### 목표 (1차)
- 왼쪽 메뉴가 있는 로컬 웹 화면과 이를 띄우는 실행 방법
- **홈**: 카테고리별 진행 상황, 다음 할 일 추천, 최근 결과물
- **모으기 › 레퍼런스 추가**: 지금 `/yt-add`가 하는 일 전체를 화면에서
- **만들기 › 콘티**: 기획안으로 콘티 만들기, 컷 단위 대안(레퍼런스 장면 + 대사 대안) 보고 클릭으로 바꾸기
- 화면에서 Claude가 필요한 일(분석, 콘티, 대사 대안)을 바로 실행

### 비목표 (이번에 안 함)
- 2차 메뉴의 실제 화면: 레퍼런스 목록, 유형화, 리포트, 모티브, 기획안, 진단, 미션. 메뉴에는 보이되 "준비 중 — 터미널에서 `/yt-coach:yt-typify`" 같은 안내만 둔다(목록을 바로 볼 수 있게 하는 것이 1차 목표의 일부라서).
- 다중 사용자, 로그인, 호스팅, 사용자별 template, 기법 중앙화, MCP 연동 — 별도 주제로 나중에 다룬다.

### 반목표 (이렇게 되면 실패)
- 화면과 md가 따로 노는 것. **md 프런트매터가 여전히 유일한 원본**이고, 화면은 그것을 읽고 쓰는 창일 뿐이다. 터미널 커맨드와 화면을 섞어 써도 결과가 같아야 한다.
- 화면이 사용자 확인 없이 AI 출력을 저장하는 것.
- 링크 자동 수집, `mine`이 유형화 기준에 섞이는 것 등 CLAUDE.md 원칙을 깨는 것.
- 외부에서 접속 가능한 서버(로컬 전용이어야 한다).

## 3. 제약

- CLAUDE.md 핵심 원칙·비용·안전 규칙을 그대로 지킨다. 영상은 하나씩 처리, 360p 이하, 다운로드 즉시 삭제, md 본문과 `## 내 메모`는 덮어쓰지 않는다.
- `scripts/*`의 JSON 계약(`main(argv) -> dict`, 실패 시 `{"error","message"}`)은 바꾸지 않는다. UI 서버는 이 계약 위에 올라간다.
- 섹션 라벨·유형 축(설계서 5절)은 바꾸지 않는다.
- Windows가 주 환경. 한글 경로·파일명이 정상 동작해야 한다.
- 별도 LLM API 키 없이 사용자의 Claude 구독(설치된 `claude` CLI)을 쓴다.
- 설계서·CLAUDE.md의 보류 항목 "웹 대시보드"를 **"로컬 UI는 허용, 호스팅·다중 사용자는 보류"**로 고친 뒤 구현한다(설계와 충돌하면 설계서를 먼저 고친다).

## 4. 사용자가 정한 것

- 로컬 전용 UI. 서버 중앙화·개인화 아님.
- 화면에서 바로 Claude를 부른다(`claude` CLI, 사용자 구독).
- **왼쪽 메뉴** 배치. 묶음: 홈 / 모으기(레퍼런스 추가, 레퍼런스 목록) / 분석(유형화, 리포트) / 만들기(모티브, 기획안, 콘티) / 성장(진단, 미션).
- 콘티 컷 대안은 **레퍼런스 실제 장면 + 대사 대안** 둘 다, **화면에서 클릭으로** 고른다.
- 1차 범위: 홈 + 왼쪽 메뉴 + 레퍼런스 추가 + 콘티. 나머지는 2차.

## 5. 구조

```
브라우저 (127.0.0.1)
   ⇄  로컬 UI 서버 (Python, 이 플러그인 안 scripts/ui 또는 ui/)
         ├─ scripts.* 를 함수로 직접 호출 (계산·저장, 기존 그대로)
         ├─ claude -p 호출 (해석: 분석·콘티·대사 대안, 기존 SKILL.md 규칙 재사용)
         └─ 작업 폴더 (YT_COACH_HOME: refs/ mine/ drafts/ workspace/ …) 읽기·쓰기
```

### 5.1 실행
- 터미널: `ytc ui` (작업 폴더 = 현재 폴더 또는 `YT_COACH_HOME`). 빈 포트로 띄우고 브라우저를 자동으로 연다.
- Windows에서 Git Bash 없이도 실행되도록 `bin/ytc.cmd`(같은 동작: venv Python 선택, 작업 폴더 전달)를 추가한다.
- Claude Code 안: `/yt-coach:yt-ui` 커맨드가 서버를 **세션과 분리된 프로세스**로 띄우고 주소를 알려 준다. Claude Code를 닫아도 서버는 남는다.
- 종료: 화면 위쪽 "서버 끄기" 버튼, 또는 `ytc ui --stop`(lock의 PID 종료). 진행 중 작업이 있으면 끄기 전에 경고한다.
- `127.0.0.1`에만 바인딩한다. 실행할 때마다 임의 토큰을 만들어 주소에 넣고, 토큰 없는 요청은 거부한다(같은 PC의 다른 프로그램·브라우저 탭이 함부로 쓰지 못하게).
- 작업 폴더가 init 전이면 홈에서 "이 폴더를 yt-coach 작업 폴더로 만들기"(`refstore init`과 같은 동작)를 안내한다.

### 5.2 Claude 호출 규약
- 서버가 `claude -p`를 하위 프로세스로 부른다. 입력은 해당 스킬의 `SKILL.md` 규칙 + 스크립트 `context` JSON, 출력은 `--output-format json` + `--json-schema`로 구조화된 JSON 하나.
- 도구는 필요한 것만 허용한다. 프레임 이미지를 봐야 하는 일(샷 분류, 말 없는 영상 분석)은 `Read`만, 나머지는 도구 없이. 작업 디렉터리는 작업 폴더.
- 세션은 남기지 않는다(`--no-session-persistence`).
- `claude`가 없거나 로그인 안 됨 → 화면에 이유와 해결 방법을 한 줄로 보여 주고, 그 기능만 막는다(다른 화면은 동작).
- 결과 JSON은 기존 스크립트의 검증(`videomd write`, `conti save` 등)을 그대로 통과해야 저장된다. 검증 실패(`invalid_*`)는 지금 커맨드처럼 message를 붙여 Claude에게 한 번 다시 시킨다. 그래도 실패하면 사용자에게 보여 준다.

### 5.3 오래 걸리는 작업
- 자막 수집, 컷 분석, STT, Claude 호출은 수 초~수 분 걸린다. 서버는 작업(job)으로 돌리고, 화면은 진행 상황을 실시간으로 받는다(SSE 또는 폴링 — 빌더 판단).
- 동시에 하나의 수집 작업만 돈다(차단 위험, "하나씩 처리" 원칙). 이미 돌고 있으면 버튼을 막고 이유를 보여 준다.
- **작업 폴더당 UI 서버는 하나**다. 서버는 `workspace/ui.lock`(PID, 포트, 토큰)을 만들고, 두 번째 `ytc ui`/`/yt-ui`는 새로 띄우지 않고 살아 있는 서버 주소를 연다(죽은 PID의 lock은 지운다). 터미널 `/yt-add`와 UI 수집이 동시에 도는 경우는 막지 않는다. 기존 `YT_FETCH_INTERVAL` 간격과 차단 시 중단 규칙으로 충분하다고 본다(`fetch.py`는 바꾸지 않음).
- 화면을 닫아도 작업은 서버에서 계속되고, 다시 열면 진행 상황이 보인다. 서버를 끄면 작업은 멈춘다(재개는 1차 범위 아님. 이미 저장된 영상은 다음 실행 때 `exists`로 건너뛴다).

## 6. 화면

### 6.1 공통 레이아웃
- 위: 앱 이름, 현재 카테고리 선택(드롭다운), 작업 폴더 경로.
- 왼쪽 메뉴: 4절의 묶음과 항목. 2차 항목은 흐리게 표시하고, 누르면 "준비 중"과 같은 일을 하는 터미널 커맨드를 보여 준다.
- 라이트·다크 테마. 지금 report·conti HTML의 색 토큰을 기준으로 맞춘다.

### 6.2 홈
- 카테고리별 진행 단계: 레퍼런스 수(ref/mine), 유형화 가능 여부와 남은 개수, 기획안 수, 콘티 수, 미션 상태. 단계 막대로 보여 주고 "지금" 단계를 표시한다.
- 다음 할 일 추천 한 줄과 바로가기 버튼(예: "레퍼런스 2개 더 모으면 유형화 가능 → 레퍼런스 추가").
- 최근 결과물: 최근 기획안·콘티·리포트 파일, 누르면 해당 화면이나 HTML로 간다.
- 이 정보는 새 스크립트 `scripts/status.py`(`ytc status [category]`)가 만든다. 같은 JSON을 터미널에서도 쓸 수 있다.
- 단계 정의(새 로직): 모으기(레퍼런스 수, 기존 `stage_text` 기준 재사용) → 유형화(typify 결과 유무) → 기획안(`drafts/`의 그 카테고리 기획안 수) → 콘티(콘티가 있는 기획안 수) → 진단(`mine/` 진단 유무). "지금"은 아직 끝나지 않은 첫 단계다. 미션은 카테고리와 무관한 날짜 단위 데이터라 단계 막대에 넣지 않고 홈에 "오늘 미션" 카드로 따로 보여 준다.

### 6.3 모으기 › 레퍼런스 추가
지금 `commands/yt-add.md`의 흐름을 화면으로 옮긴다. 규칙·분기는 그 문서와 같다.

1. **입력**: 카테고리(드롭다운), 구분(레퍼런스 / 내 영상), 링크 여러 줄. 옵션은 체크박스: 샷 분류도 함께(`--shots`), 다시 분석(`--force`), 자막·컷 새로 받기(`--refetch`, 차단 위험 경고 문구 포함). 별도 버튼 "샷 분류만 보강"(`--shots-only`).
2. **진행**: 영상마다 줄 하나 — 자막 → 컷 → 분석 → 확인 대기 / 저장됨 / 건너뜀 / 실패. 실패는 이유 한 줄.
   - `blocked`/`proxy_failed`: 남은 영상 전부 중단하고 프록시 안내를 보여 준다.
   - `no_transcript`: 그 영상 줄에서 "음성 인식(STT)으로 / 화면만 보고 분석" 중 고르게 한다.
3. **확인**: Claude 분석 결과를 카드로 보여 준다(제목·길이·자막 출처, 한 줄 요약, 훅·서사, 평균 컷, 섹션 타임라인, 기법, 프레임 썸네일 줄).
   - 섹션 라벨은 드롭다운으로 고칠 수 있다(어휘는 `videomd`의 상수에서 가져온다).
   - 버튼: 저장 / 남은 영상 모두 저장 / 건너뛰기 / 고칠 점 입력 후 다시 분석(CLI의 "고칠 점"과 같다: 입력한 글을 붙여 Claude에게 다시 시킨다).
   - 저장을 눌러야만 `videomd write`가 실행된다.
4. **마무리**: 저장·건너뜀·실패 개수, 기법 카탈로그 변화, `stage_text`. "분석이 틀리면 md를 고치고 `reviewed: true`" 안내.

### 6.4 만들기 › 콘티
1. **목록**: `drafts/`의 기획안과 각 기획안의 콘티 유무. 기획안을 고르면 "콘티 만들기"(이미 있으면 "다시 만들기 — 내 메모는 남습니다").
2. **만들기**: `conti context` → Claude(yt-conti 규칙) → 미리보기(지금 SKILL 6절 형식에 해당하는 표) → 저장 버튼을 눌러야 `conti save`. 경고(`line_too_long`, `script_mismatch`)는 해당 컷에 표시한다.
3. **편집 화면**: 왼쪽은 컷 목록(번호, 섹션, 샷 크기, 길이, 대사, 스케치와 현재 참고 프레임 썸네일). 컷을 누르면 오른쪽 패널:
   - **레퍼런스 실제 장면**: 같은 샷 크기+섹션 → 같은 샷 크기 순으로 최대 6장(exact가 approx보다 먼저, approx는 "근사" 표시). `conti.frame_pool`과 같은 기준. 하나를 누르면 이 컷의 참고 프레임으로 고정된다.
   - **대사 대안**: 처음 3개, "대안 더 보기"로 3개씩 추가. 각 대안에 글자 수 / 이 컷 최대 글자 수를 표시하고 넘으면 경고색.
   - **이걸로 바꾸기**: 그 컷의 `line`을 바꾸고 저장한 뒤 HTML을 다시 그린다.
4. 화면에서 `guide`·`caption`·`sfx`도 직접 고칠 수 있다(텍스트 입력, 저장 버튼). 1차에서 샷 크기·컷 길이·컷 추가/삭제는 하지 않는다(md 직접 수정 + 다시 그리기는 지금처럼 가능).

#### 대사 대안 생성 규칙
- 입력: 이 컷의 섹션 정보, 앞뒤 컷의 `line`, 이 컷의 `caption`·`guide`·샷 크기, 섹션의 전체 대사, 말 속도와 이 컷 최대 글자 수(`speech_cps × sec`, 기존 `line_too_long` 기준과 같게), 기획안의 훅·서사 유형, profile.
- 출력: 대안 N개, 각각 대사와 한 줄 의도(예: "더 짧고 리액션 중심").
- 서로 다른 방향으로 쓴다(같은 말 바꿔 쓰기 금지). 훅 섹션은 hook_type을 지킨다.
- 규칙은 `skills/yt-conti/SKILL.md`에 "컷 대사 대안" 절로 추가한다(CLI와 UI가 같은 규칙을 쓰게).

#### 콘티 md 반영 규칙
- 컷 `line`을 바꾸면 그 섹션의 `script[].text`를 컷 `line`들을 이은 것으로 다시 맞춘다(`script_mismatch`가 생기지 않게).
- 참고 프레임 고정은 컷에 선택 필드 `ref_frame`(작업 폴더 기준 프레임 경로)으로 저장한다. `render`는 `ref_frame`이 있으면 자동 매칭 대신 그것을 쓴다. 필드 추가이므로 콘티 `schema_version`을 올리고, 없는 기존 파일은 지금처럼 자동 매칭한다.
- md 본문은 지금 `save`처럼 프런트매터에서 다시 그리고 `## 내 메모`는 보존한다. 저장 후 HTML도 다시 그린다.
- 위 동작은 `scripts/conti.py`에 함수(예: `update_cut`)로 넣고 CLI 서브커맨드로도 노출한다. UI 서버는 그 함수를 부른다.

#### 화면 밖 수정과의 충돌
- 화면은 파일을 열 때 내용 해시를 받아 두고, 저장 요청에 그 해시를 같이 보낸다. 그사이 파일이 바뀌었으면 저장하지 않고 "파일이 밖에서 바뀌었습니다 — 다시 불러오기"를 보여 준다(`update_cut`이 기대 해시 인자를 받는다).

#### 콘티 다시 만들기
- 다시 만들면 프런트매터는 새 Claude 출력으로 바뀐다. 화면에서 바꾼 대사·가이드·고정한 참고 프레임은 사라지고 `## 내 메모`만 남는다. 버튼을 누르기 전에 이 사실을 경고 문구로 보여 준다.

## 7. 저장 확인 원칙과 화면의 관계
- "AI 출력은 제안, 저장 전 사용자 확인"은 **저장 버튼·이걸로 바꾸기 클릭**으로 충족한다. 클릭한 뒤 다시 묻지 않는다.
- AI 출력이 사용자 클릭 없이 파일에 쓰이는 경로는 없다. 예외는 지금 커맨드에도 있는 자동 처리뿐이다(`--shots-only`의 확인 없는 저장, `script_mismatch` 자동 맞춤).

## 8. 테스트와 완료 확인
- 새 스크립트·함수(`status`, `conti update_cut`, `ref_frame` 렌더)는 기존 방식대로 pytest.
- UI 서버의 엔드포인트는 테스트 클라이언트로 pytest. `claude` 호출과 수집(`fetch`)은 가짜로 바꿔 끼운다. 토큰 없는 요청 거부, 로컬 바인딩도 테스트한다.
- PLAN 규칙대로 완료 조건은 실제로 확인한다: `tests/fixtures/links.txt`의 링크 2~3개를 화면에서 추가·저장, 기존 콘티에서 컷 하나의 대사 대안 받기·바꾸기·참고 프레임 고정 후 HTML 육안 확인. Chrome 헤드리스 스크린샷으로 레이아웃 확인.

## 11. 내가 정한 것 (사용자 확인 필요)
- 작업 폴더당 UI 서버 하나, 터미널 수집과의 동시 실행은 막지 않음(5.3).
- Windows용 `bin/ytc.cmd` 추가, `/yt-ui` 서버는 세션과 분리(5.1).
- 화면 밖 수정은 해시로 감지해 저장 거부 후 다시 불러오기(6.4).
- 콘티 다시 만들기는 화면 수정분을 버리고 경고만 함(6.4).
- 분석 확인에 "고칠 점 입력 후 다시 분석" 포함(6.3).
- 홈 단계는 새 판정 로직, 미션은 단계 막대 밖 별도 카드(6.2).
- 데이터는 작업 폴더 md 그대로, 새 저장소 없음.
- 서버는 Python, 기존 scripts를 함수로 직접 호출.
- 클릭 = 저장 확인(7절).
- 실행은 `ytc ui` + `/yt-coach:yt-ui`.
- 대안은 처음 3개, 레퍼런스 장면은 최대 6장.
- 참고 프레임 클릭 시 컷에 고정(`ref_frame` 필드 추가).
- 콘티 편집 1차 범위: 대사·가이드·자막·효과음까지, 샷 크기·길이·컷 추가/삭제는 제외.
