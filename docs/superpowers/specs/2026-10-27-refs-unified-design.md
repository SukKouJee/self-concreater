# 레퍼런스 화면 합치기 + 추가 흐름 다듬기 — 설계

날짜: 2026-10-27 · 대상: 로컬 UI(`ytc ui`)의 레퍼런스 추가(`#/add`)·레퍼런스 목록(`#/refs`)

## 왜

사용자 말: "레퍼런스와 추가와 목록은 합칠 수 있지 않을까", "레퍼런스를 넣을 때 조작이 세련되지 못하다".
사용자가 고른 불편 네 가지(모두):

1. 영상마다 저장을 눌러야 다음 영상으로 넘어간다. 여러 개를 넣고 자리를 비울 수 없다.
2. 링크 입력칸이 날것 그대로다. 시작 전에는 몇 개인지, 잘못된 링크·이미 있는 영상인지 모른다.
3. 옵션이 어렵고 많다: 카테고리 선택(상단과 중복), 체크박스 3개, "샷 분류만 보강" 버튼이 한꺼번에 보인다.
4. 확인 화면(분석 결과 카드)이 길고, 무엇을 보고 저장해야 하는지 한눈에 안 들어온다.

성공 기준: 링크를 붙여 넣고 시작한 뒤 자리를 비웠다가 돌아오면, 분석이 끝난 영상들이 "확인 대기"로
모여 있고, 요약만 훑어 한 번에(또는 하나씩) 저장할 수 있다. 추가와 목록 사이를 메뉴로 오갈 일이 없다.

## 지켜야 할 것 (CLAUDE.md·설계서)

- AI 출력은 제안이다. **영상 md는 사용자가 저장을 눌러야 쓴다**("확인 없이 자동 저장" 옵션은 만들지 않는다).
- 영상은 하나씩 처리한다(동시 다운로드·동시 분석 없음). 360p 이하, 다운로드 영상은 프레임 추출 직후 삭제.
- 링크 자동 수집(채널·재생목록 펼치기)은 하지 않는다. 그런 링크는 "영상 링크가 아님"으로 표시만 한다.
- 화면은 외부 주소를 쓰지 않는다(썸네일을 유튜브에서 불러오지 않는다).
- 디자인은 2026-10-26 shadcn 모양(토큰·컴포넌트 규칙)을 따른다.

## 결정한 것

### A. 화면 하나: "레퍼런스" (`#/refs`)

- 메뉴 "모으기"는 **레퍼런스**, **공용 라이브러리** 두 개가 된다. "레퍼런스 추가" 메뉴는 없어진다.
- 위에서부터: 제목줄(제목 + 개수 + 오른쪽 `+ 링크 추가` 주요 버튼) → 추가 칸(접힘/펼침) →
  진행 카드(작업이 있을 때만) → 확인 대기 묶음(있을 때만) → 필터·검색·정렬 → 카드 목록.
- `#/add`로 들어오면(홈 "다음 할 일", 가이드, 도움말, 다른 화면의 링크) `#/refs`로 바꾸고 추가 칸을 펼친다.
  안의 링크(`#/add`)들은 그대로 둬도 동작하지만, 문구 "레퍼런스 추가로 가기"는 "레퍼런스 넣기"로 바꾼다.
- 영상 하나가 저장되면 목록을 다시 불러와 그 카드가 맨 앞(최근 추가순일 때)에 나타난다.
- 상세(`#/refs/<id>`)는 그대로.
- 내 판단: 레퍼런스가 0개인 카테고리에서는 추가 칸을 처음부터 펼친다.

### B. 링크 입력: 붙여 넣는 즉시 정리된 목록으로

- 입력칸은 여러 줄 글상자 그대로 두되(붙여 넣기가 가장 빠르다), 바로 아래에 **링크 목록**이 실시간으로 나온다.
  줄마다 상태 하나:
  - `새 영상` — 분석한다.
  - `이미 있음` — 이 카테고리에 md가 있다. 제목을 함께 보여 주고 건너뛴다("다시 분석"을 켜면 `다시 분석`으로 바뀐다).
  - `다른 구분으로 있음` — 같은 카테고리에 다른 role(ref/mine)로 있다. 건너뛴다(설계서: 동시 등록 불가).
  - `중복` — 같은 목록 안에 이미 있는 영상.
  - `영상 링크 아님` — 유튜브 영상 id를 못 찾음(채널·재생목록 포함).
  줄마다 `×`로 그 줄을 지울 수 있다(글상자에서도 지워진다).
- 시작 버튼 문구에 실제 개수가 들어간다: `영상 3개 분석 시작`. 분석할 게 0개면 버튼을 끈다.
- 서버: `POST /api/add/check {category, role, links}` → 줄마다 `{link, id, status, title}`.
  기존 `parse_links`와 `refstore.find_video`를 쓴다. 입력이 멈추고 300ms 뒤에 부른다(내 판단).
- 새 영상의 제목은 알 수 없다(네트워크를 쓰지 않는다). id만 보인다.

### C. 옵션 줄이기

- 카테고리 선택칸을 없애고 상단 카테고리를 쓴다. 추가 칸 머리에 "travel 카테고리에 넣습니다"라고 적는다.
- 보이는 옵션: 구분(레퍼런스 / 내 영상) 토글, `샷 분류도 함께`(설명: "Claude 호출이 영상마다 한 번 더").
- `고급` 접기 안: `이미 분석한 영상도 다시 분석`, `자막·컷을 새로 받기`, `자막이 없을 때`(음성 인식 / 화면만 보고 분석 / 건너뛰기, 기본 음성 인식).
  → 자막이 없을 때 묻느라 멈추던 것도 없어진다(미리 고른 대로 진행).
- `샷 분류만 보강` 버튼은 추가 칸에서 빼서, 목록 도구줄에 **보강할 영상이 있을 때만** `샷 분류 보강 (N개)`로 보인다.

### D. 확인을 기다리지 않고 다음 영상으로

- 작업은 영상을 차례로 받고·자르고·분석한다. 분석이 끝난 영상은 **확인 대기**에 들어가고, 작업은 곧바로 다음 영상으로 간다.
- 사용자가 저장하면 md를 바로 쓴다(빠름). `샷 분류도 함께`면 그 영상의 샷 분류를 **작업 줄 뒤에** 붙인다(Claude 호출이라 하나씩).
- `다시 분석`(고칠 점 입력)도 작업 줄 뒤에 붙는다. 그동안 그 영상은 "다시 분석 대기 → 분석 중"으로 보인다.
- 작업은 줄이 비고 확인 대기가 없어야 끝난다. 줄은 비었는데 확인 대기만 남으면 진행 카드는
  "확인을 기다리는 영상 N개"를 보인다.
- `모두 저장`은 지금 확인 대기에 있는 영상 전부를 저장한다(이후 들어오는 영상은 다시 확인을 받는다 — 내 판단,
  지금의 "이후 전부 자동 저장"보다 원칙에 맞다).
- 멈추기(취소): 진행 중인 영상만 멈추고, 이미 확인 대기에 있는 영상은 그대로 저장·건너뛰기 할 수 있다.
- 저장 안 한 분석 결과는 지금처럼 서버 메모리에만 있다. UI 서버를 끄면 사라진다고 확인 대기 묶음에 한 줄로 알린다(내 판단: 파일 보관은 이번 범위 밖).

### E. 확인 카드: 요약 먼저, 자세히는 접기

- 확인 대기 묶음 머리: "확인 대기 3개" + `모두 저장` 버튼.
- 카드 하나(접힌 상태가 기본):
  - 제목 · 길이 · 채널
  - 섹션 띠(색 막대, 목록 카드와 같은 모양) + 훅 · 서사 · 형식 꼬리표(한국어 이름)
  - 한 줄 요약
  - 경고가 있으면 한 줄(예: "자막이 없어 화면만 보고 분석했습니다")
  - 버튼: `저장`(주요), `고칠 점 적고 다시 분석`, `건너뛰기`, `자세히`
- `자세히`를 펼치면 섹션별 시간·라벨·내용 표, 시놉시스, 기법 목록, 라벨을 고칠 수 있는 지금의 편집 기능.
- 키보드: 카드마다 버튼이 순서대로 포커스. 저장·건너뛰기 뒤 포커스는 다음 카드의 `저장`으로(없으면 묶음 머리로).

### F. 작업 줄 모델 (빌더 질문에 대한 결정 — 모두 내 판단)

- **도는 중에도 링크를 더 넣을 수 있다.** 새 링크는 지금 작업의 줄 끝에 붙는다(작업은 계속 하나뿐).
  그래서 옵션(구분·샷 분류·다시 분석·자막·컷 새로 받기·자막이 없을 때)과 **카테고리는 영상(항목)마다** 들고 있다.
- 줄에 오르는 일은 세 가지: 영상 분석(받기→컷→분석), 다시 분석(의견 포함), 저장된 영상의 샷 분류. 워커는 이것을 하나씩 처리한다.
- **저장은 요청을 받은 쪽이 바로 쓴다**(`videomd.write`는 Claude를 부르지 않고 빠르다). 같은 영상에 대한 쓰기·결정은 잠금으로 겹치지 않게 한다.
  "영상은 하나씩"은 받기·분석(무거운 일)에 대한 규칙이고, 저장은 여기에 걸리지 않는다.
- **작업이 멈추거나(취소, Claude 호출 불가 같은 중단 코드) 실패해도 확인 대기 영상은 남는다.** 저장·건너뛰기를 계속 받는다.
  다시 분석은 작업이 다시 돌 때만 가능하다(멈춘 작업에서는 버튼을 끄고 이유를 보인다). 확인 대기가 모두 처리되면 작업이 닫힌다.
- **`모두 저장` 중 하나가 실패하면** 나머지는 계속 저장하고, 실패한 카드에 이유를 보인 채 확인 대기에 남긴다.
  응답은 영상별 결과 목록.
- **카테고리를 바꾸면**: 진행 카드·확인 대기는 그 영상의 카테고리 화면에만 보인다. 다른 카테고리 화면에는
  "travel 카테고리에서 분석 중 · 확인 대기 2개 — 보기" 한 줄만 보인다.
- `/api/add/check`의 "다른 구분으로 있음"은 같은 카테고리에서 role만 다른 md를 찾는다(`find_video`가 role을 돌려준다).

## 범위 밖

- 썸네일·제목을 미리 가져오기(네트워크), 분석 결과 파일 보관, 동시 분석, 자동 저장.
- 터미널 커맨드(`/yt-add`) 흐름 변경.

## 빌더에게 맡기는 것

- 진행 카드(2026-10-25 원형 진행률·남은 시간)와 단계 칸은 지금 코드를 옮겨 쓴다. 여러 영상 진행은 "지금 영상" 하나만 크게.
- `add.js`와 `refs.js`를 합칠지, `refs.js`가 추가 부분 모듈을 불러 쓸지는 빌더 판단(파일 하나가 너무 커지지 않게).
- 작업 상태 모델(대기 줄, 확인 대기 상태 값 이름)과 API 모양은 기존 jobs/decision API를 최대한 살려서.

## 디자인

- 토큰·컴포넌트는 `app.css`의 shadcn 규칙. 새 색은 만들지 않는다.
- 상태 꼬리표 색: 새 영상 = 기본 배지, 이미 있음·중복 = 흐린 배지, 영상 링크 아님 = 위험색 글자 + 아이콘.
